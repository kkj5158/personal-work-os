## 보존한 수면 정책

주간은 월–일이며 시간표는 **전일18시–당일18시, 시간당26px**다. 실제 감사 소스에 비선형 확대 band나 낮잠 전용 시간축은 없었다. 정방향·역방향 변환이 같은 척도를 사용하며 자정·아침·낮잠 시간대 경계와 원본 날짜를 검증했다. 일별00–24시, 월간42칸 및 원본 귀속 규칙도 유지했다.

야간은 원본 기상/예정일, 낮잠은 원본 시작 현지 날짜에 귀속된다. 긴 구간과 자정을 넘긴 구간은 원본 ID 하나를 유지한다. 낮잠 API/identity, 겹침 차단, 제외, 양 끝 timezone·offset·초, DST gap 거절/fold 선택, 미래 시각 제한과 18시간 이상 확인은 기존 계약을 따른다. 드래그로 수면 종류를 바꾸지 않는다.

삭제는 확인 후 영구 삭제이며 삭제 Undo는 없다. 기존 주수면 수정 Undo 8초를 유지하고 브라우저에서 실제 복원을 확인했다. owner별 초안 보관, 미확인 요청의 동일 operationId/body 재시도, 이동/새로고침 보호, 서버 확인 후 재조회도 유지했다.

최신 서버의 주수면 수동 수정/주석은 이전 revision 입력을 병합하도록 설계돼 있다. 웹은 최초 POST 전에 canonical revision을 조회하여 달라졌으면 입력을 보존하고 비교·재적용을 요구한다. 낮잠·삭제는 기존 서버의 엄격한 revision 검사를 그대로 사용한다. **웹 사전 조회와 POST 사이까지 원자적 CAS가 되는 것은 아니다.** 기존 수동 우선 서버 의미를 바꾸지 않았으며, 더 강한 서버 CAS를 이번 구현의 검증 결과로 주장하지 않는다.
