## 보존할 서버 정책

SleepService와 Sleep Web V1 계약을 확인했다. nap은 별도 sleep_naps 및 별도 API identity다. 동일 owner transaction lock으로 nap/nap·nap/main 겹침을 차단하고 경계 인접은 허용한다. OPEN은 끝없는 구간으로 취급한다. main/main·제외 규칙은 기존 서버를 따른다. 낮잠·삭제는 revision 충돌을 atomic하게 거절한다. 실제 최신 SleepService의 주수면 CORRECT/ANNOTATE는 mergeVersion으로 이전 revision의 명시적 수동 입력을 허용한다(자동 추정보다 수동 우선). 기존 계약 문서의 엄격 충돌 설명은 이 부분에서 오래됐다. 서버 의미를 바꾸지 않고 웹의 최초 전송 전에 canonical revision을 비교해 다르면 비교/재적용을 요구한다. 비교와 POST 사이의 경합까지 atomic CAS로 바꾸지는 않는다. 응답 불명 replay에는 이 비교를 다시 적용하지 않는다. Android 동기화 프로토콜과 감지 로직은 수정하지 않는다.

## 지표 정의와 조회 범위

선택 날짜가 속한 월–일을 사용한다. 주수면 평균은 해당 주 적격 CLOSED 세션의 canonical interval 평균이며 누락을0으로 채우지 않는다. 날짜별 차트는 같은 귀속일의 적격 주수면 interval 합계다. 집계 제외건은 표시를 켜도 지표에 들어가지 않는다.

낮잠 횟수 평균은 적격 nap 수/달력일 수다. 과거 주는7, 진행 중 주는 월요일부터 서버 현재 KST 날짜까지(오늘 포함), 미래 주는 분모0으로 계산 불가다. nap은 main recordingStartDate와 독립이라는 기존 계약에 따라 main 추적 시작일로 분모를 자르지 않는다. 낮잠 시간 평균은 총 interval/nap 수이며 기록이 없으면 미기록이다.

일·월 보기에서도 지표는 선택 날짜의 주간을 표시하므로 기존 view range와 주간 range의 합집합을 기존 intervals API로 읽는다. API의63일 제한 안이다. 마지막 확인된 서버 값만 사용하고 조회 실패·로딩 중 다른 주의 값을 현재 주로 오표시하지 않는다.

## 검증 계획·위험

비선형 band가 실제로 없다는 점, WORK FLOW의 당일 경계와 Sleep의 overnight 차이를 adapter 이전에 기록했다. Sleep 기존 geometry·snap5분 편집은 보존하고 신규 빈공간 생성만 WORK FLOW15분 단위를 사용한다. 공통 스냅 추출은 기존 WORK FLOW 회귀 테스트로 보호한다.

격리된 새 loopback PostgreSQL과 DEV profile API/production Next build에서 합성 owner만 사용한다. UI pointer/keyboard, 실제 API 저장·새로고침·충돌·삭제, analytics, WORK FLOW 인접 회귀를 확인한다. hosted DEV에는 검증한 frontend만 배포하고 인증·조회 smoke를 수행한다. PROD 배포·운영 fixture·Android/실기기 QA는 이번 범위에 포함하지 않는다.

## 검증 중 발견·조치

빈 열 생성·날짜 열 이동에 같은 기존 TimeCalendar를 사용한다. 이동 미리보기로 원본 DOM 블록이 다른 열로 옮겨져도 gesture를 유지하도록 pointer capture를 안정적인 grid에 둔다. 단순 클릭은 capture 종료 시 원래 블록으로 명시 전달한다. 이동을 원래 시간으로 되돌릴 때는 원본 exact seconds와 offset을 복원하고 입력 중 점수·메모는 유지한다. 각각 회귀 테스트를 추가했다.
