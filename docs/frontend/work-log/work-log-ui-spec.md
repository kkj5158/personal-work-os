# Personal Work OS — Work Log UI 확정 핸드오프

> 이 문서는 사용자가 제공한 한국어 handoff 원문을 요약·재해석 없이 그대로 보존한 것이다.
> 최종 확정 시안 이미지: [`./work-log-ui-final.png`](./work-log-ui-final.png)

## 1. 프로젝트 개요

Personal Work OS는 개인의 계획·실행·근무기록·분석을 한곳에서 관리하는 데스크톱 웹앱이다.

현재 우선순위는 전체 앱을 한꺼번에 완성하는 것이 아니라, Work Log(근무 기록) 화면부터 실제로 사용할 수 있는 수준으로 완성하는 것이다.

현재 단계에서는 모바일 사용을 상정하지 않는다. 반응형 모바일 UI, Drawer 전환 등은 이번 작업 범위에서 제외하고 데스크톱 화면에 집중한다.

## 2. 디자인 기준

이 핸드오프와 함께 전달되는 이미지를 Work Log 화면의 최종 확정 시안이자 시각적 기준으로 사용한다.

전체 디자인 방향은 다음과 같다.

- 기본 테마: GitHub Light
- 흰색·아주 옅은 회색 중심의 평평한 화면
- 얇은 회색 테두리와 격자로 영역 구분
- 그림자, 그라데이션, 발광 효과 최소화
- 파란색은 선택·포커스·링크에 제한적으로 사용
- 초록색은 근무 상태나 저장 버튼 등 긍정적 의미에 사용
- 상태값은 GitHub Label과 유사한 배지 형태
- 둥근 모서리는 과도하게 사용하지 않음
- 운영 도구처럼 정보 밀도가 높고 정돈된 데스크톱 UI
- 테이블은 모든 열의 세로·가로 격자가 명확하게 보여야 함

기존의 일반적인 다크 SaaS 관리자 화면 느낌은 사용하지 않는다. 별도 요청이 없다면 앞으로 Personal Work OS의 모든 화면은 GitHub Light를 기본 기준으로 잡는다.

## 3. 전체 화면 구조

Work Log 화면은 다음 다섯 영역으로 구성한다.

1. 왼쪽 전역 사이드바
2. 상단 조회 기간 및 검색·필터 도구
3. 중앙 주간 근무 기록 테이블
4. 오른쪽 선택 날짜 상세 편집 패널
5. 하단 주간 요약

이 화면의 핵심 역할은 다음과 같다.

한 주의 근무기록을 빠르게 검토하고, 선택한 날짜의 상세 기록을 확인·수정하는 화면.

테이블은 주간 비교와 검토가 중심이고, 세부 입력·수정은 오른쪽 상세 패널에서 처리한다.

## 4. 사이드바 용어

사이드바 메뉴는 다음과 같이 한국어로 표시한다.

- Dashboard → 대시보드
- Planning → 계획
- Execution → 실행
- Review → 회고
- Work Log → 근무 기록
- Analytics → 분석
- Settings → 설정

현재 선택된 `근무 기록` 메뉴는 이미지처럼 활성 상태가 명확하게 보여야 한다.

제품명 `Personal Work OS`는 영문을 유지한다.

## 5. 상단 도구 영역

상단 화면 제목은 `근무 기록`으로 표시한다.

기간 단위:

- Week → 주
- Month → 월
- Custom → 사용자 지정

주간 이동 용어:

- Previous week → 저번 주
- Today → 오늘
- Next week → 다음 주

그 밖의 도구:

- Search → 검색
- Filter → 필터
- Columns → 열 설정

날짜 범위는 `2026.08.10–2026.08.16`처럼 숫자 중심으로 간결하게 표시한다.

## 6. 주간 테이블 확정 구조

테이블 열은 다음 순서로 고정한다.

`요일 | 날짜 | 출결 | 출퇴근 | 체류 시간 | 실근무 | 점수 | 메모`

### 요일

요일은 중요도가 높으므로 테이블의 가장 왼쪽에 독립된 열로 둔다.

축약형이 아니라 다음과 같이 한국어 전체 요일명을 사용한다.

- 월요일
- 화요일
- 수요일
- 목요일
- 금요일
- 토요일
- 일요일

요일과 날짜를 한 셀에 합치지 않는다.

### 출결

기존 `Status`는 `출결`로 번역한다.

출결 상태값은 다음 5개만 사용한다.

- 근무
- 휴일
- 연차
- 병가
- 조퇴

`Day Off`는 `휴무`가 아니라 반드시 `휴일`로 표시한다.

상태값은 색상이 절제된 작은 배지로 보여준다.

### 출퇴근

출근 시간과 퇴근 시간을 테이블에서 하나의 열로 합친다.

기본 표시:

`09:12–18:02`

지각한 날에는 같은 셀 안에 조건부로 지각 정보를 추가한다.

예:

`12분 지각`

지각하지 않은 날에는 지각 문구를 표시하지 않는다.

### 체류 시간

기존 `Basic Work`의 최종 한국어 명칭은 `체류 시간`이다.

출근 시간부터 퇴근 시간까지를 기준으로 자동 계산되는 시간값이다.

테이블과 오른쪽 상세 패널, 하단 주간 요약에서 모두 동일한 용어를 사용한다.

### 실근무

기존 `Net Work`의 최종 한국어 명칭은 `실근무`이다.

체류 시간을 기준으로 실제 인정할 근무시간을 나타내며, 오른쪽 상세 패널에서 필요하면 직접 조정할 수 있다.

테이블에서는 `체류 시간` 바로 오른쪽에 배치한다.

### 작업 블록 합계

기존 `Actual Blocks`의 최종 한국어 명칭은 `작업 블록 합계`이다.

Planning/Execution에서 기록된 실제 작업 블록의 합산값이며 읽기 전용으로 취급한다.

중요한 노출 규칙:

- 중앙 테이블에는 표시하지 않는다.
- 행을 선택했을 때 오른쪽 상세 패널에서 표시한다.
- 하단 주간 요약에서 합계값을 표시한다.

### 점수

점수는 100점 만점이다.

표시 방식:

- 숫자만 표시
- 숫자 옆에 원형 진행 링 표시
- `82 / 100`처럼 `/ 100`을 붙이지 않음
- 별 아이콘을 사용하지 않음
- 하단의 평균 점수도 동일한 원형 진행 표현 사용

### 메모

테이블에서는 한 줄 미리보기만 보여준다.

내용이 길면 잘라서 표시하고, 전체 내용의 확인과 수정은 오른쪽 상세 패널에서 처리한다.

## 7. 근무 장소

근무 장소는 일별 비교 필요성이 낮고 기본값을 주로 사용하므로 중앙 테이블에서는 완전히 제외한다.

근무 장소는 오른쪽 상세 패널에서만 확인하고 수정한다.

현재 기본 장소의 화면 표시명은 다음과 같다.

`다올 사무실`

기존 `Office`나 `다올 오피스`라는 표현은 사용하지 않는다.

내부 DB 값은 기존 영문 코드 등을 유지해도 무방하지만, 사용자 화면에는 `다올 사무실`로 표시한다.

## 8. 오른쪽 상세 패널

테이블의 행을 클릭하면 해당 날짜가 선택되고, 오른쪽 패널에 전체 내용이 표시된다.

주요 표시 항목:

- 날짜
- 출결
- 근무 장소
- 출근 시간
- 퇴근 시간
- 체류 시간
- 실근무
- 작업 블록 합계
- 지각
- 근무 점수
- 메모

상세 패널 용어:

- Record details → 근무 기록 상세
- Status → 출결
- Location → 근무 장소
- Clock In → 출근 시간
- Clock Out → 퇴근 시간
- Work time → 근무 시간
- Basic Work → 체류 시간
- Auto-calculated → 자동 계산
- Net Work → 실근무
- Manually adjust time → 직접 조정
- Actual Blocks → 작업 블록 합계
- Read-only summary → 읽기 전용 합계
- Late → 지각
- Work Score → 근무 점수
- Memo → 메모
- Cancel → 취소
- Save changes → 변경사항 저장

동작 기준:

- `체류 시간`은 자동 계산값
- `실근무`는 사용자가 조정 가능
- `작업 블록 합계`는 실행 기록에서 계산된 읽기 전용 값
- 장소 기본 표시값은 `다올 사무실`
- 저장 전에는 기존 기록을 임의로 변경하지 않음

## 9. 하단 주간 요약

하단에는 현재 조회 중인 주간 범위의 요약을 표시한다.

제목 예시:

`2026.08.10–2026.08.16 주간 요약`

기본 요약 항목:

- 체류 시간 합계
- 실근무 합계
- 작업 블록 합계
- 평균 점수
- 근무일

`작업 블록 합계`는 테이블에서는 제외하지만 주간 요약에서는 유지한다.

평균 점수는 숫자와 원형 진행 링으로 표시한다.

## 10. 기본 상호작용

- 행 클릭 → 해당 행 선택 및 오른쪽 상세 패널 갱신
- 선택 행 → 강한 파란 면이 아니라 옅은 파란 배경과 좁은 강조선 사용
- 출결 배지 → 상태에 맞는 절제된 색상 사용
- 검색 → 현재 근무 기록 검색
- 필터 → 출결이나 기간 조건 필터링
- 열 설정 → 향후 표시 열을 조절할 수 있는 진입점
- 취소 → 수정 내용 폐기
- 변경사항 저장 → 선택 날짜 기록 저장
- 하단 요약 → 현재 조회 기간을 기준으로 계산

## 11. 구현 시 반드시 지킬 사항

- 첨부된 확정 이미지를 임의로 재해석하거나 전면 재설계하지 않는다.
- 모바일 UI는 현재 구현 범위에서 제외한다.
- GitHub Light 스타일을 유지한다.
- 테이블 열 순서와 용어를 임의로 변경하지 않는다.
- 근무 장소를 테이블에 다시 추가하지 않는다.
- 작업 블록 합계를 테이블 열로 추가하지 않는다.
- 점수에 `/ 100`을 표시하지 않는다.
- 요일을 날짜와 합치거나 영문 축약형으로 바꾸지 않는다.
- 출결 상태값을 확정된 5개 외에 임의로 추가하지 않는다.
- 한국어 UI 안에 불필요한 영문 라벨을 혼용하지 않는다.
- 기존 기능이나 데이터 구조를 변경해야 한다면 먼저 현재 코드와 스키마를 확인하고 영향 범위를 보고한다.
- 한 번에 큰 범위를 수정하기보다 작은 안정 단위로 구현하고 검증한다.

## 12. 현재 확정 상태와 다음 작업

Work Log의 화면 디자인과 사용자 노출 용어는 확정되었다.

다음 단계에서는 이 시안과 명세를 기준으로 현재 프론트엔드 코드 구조를 확인한 뒤, Claude Code에 전달할 구현 작업을 작은 단위로 나누어 진행한다.

권장 구현 순서:

1. GitHub Light 디자인 토큰과 공통 스타일 정리
2. Work Log의 전체 데스크톱 레이아웃 구성
3. 상단 기간·검색·필터 영역 구현
4. 주간 테이블과 출결 배지 구현
5. 행 선택 및 오른쪽 상세 패널 연결
6. 시간값과 점수 표시 방식 구현
7. 하단 주간 요약 구현
8. 실제 데이터 및 저장 동작 연결
9. 최종 시각 비교와 동작 검증

## 13. 유예된 비즈니스 규칙 (구현 차단 요소 아님)

다음 항목은 아직 확정되지 않았다. 정적 UI 구현을 진행하되, 아래 값을 임의로 발명하거나 하드코딩하지 않고 이후 데이터 통합 단계에서 정의한다:

- 지각(遲刻) 판정에 사용할 기준(출처) 및 임계값(threshold)
- 조퇴 판정 규칙
- 조퇴가 주간 근무일수(근무일)에 포함되는지 여부
- 지각 또는 조퇴가 근무 점수에 영향을 주는지 여부

지각·조퇴의 UI상 위치와 라벨(예: 출퇴근 셀의 `12분 지각`, 상세 패널의 `지각` 필드)은 이미 확정되어 있다. 유예되는 것은 오직 그 값을 계산·집계하는 로직뿐이다.
