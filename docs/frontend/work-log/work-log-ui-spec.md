## 0. v1 → v2 변경 이력

- 화면 상단의 "근무 기록" 페이지 타이틀 제거 — 전역 사이드바가 이미 내비게이션 컨텍스트를 제공하므로 중복.
- 본문 영역을 화면 전체에 늘려 채우지 않고, 적정 최대 너비로 중앙 정렬(좌우 여백 균형).
- 상시 노출되던 우측 상세 패널을 **완전히 제거**. 행 클릭 시 모달로 대체.
- 상단에 새로운 개요 영역 추가: (1) 월간 출결 도넛 차트, (2) 오늘의 근무 패널, (3) 오늘의 근무 요약 패널.
- 주간 테이블에 `지각` 전용 컬럼 추가, `출퇴근` 컬럼에서 지각 텍스트 중복 제거.
- 출퇴근 시간 표기를 24시간제에서 12시간 AM/PM 표기로 변경 (예: `09:12 AM`).
- 근무 장소 기본 표시값을 `다올 사무실`에서 `카프카 사무실`로 변경.
- `근무 기록 상세`가 상시 패널에서 **모달**로 전환, 조회 모드로 열리고 `수정` 버튼을 눌러야 편집 가능.
- `업무시간 기록` 모달 신설 — 가산형(additive) 시간 기록 모델. 항목별 기록의 합이 그날의 `실근무`가 됨.
- `기간 단위`에서 `사용자 지정` 제외 — `주`, `월`만 구현.
- 주간/월간 요약 아래에 근무 추이 차트 2종(`주간 실근무 시간`, `주간 평균 점수`) 추가.
- 월간 뷰 신설 — 주 단위로 그룹화된 블록.
- `조퇴`가 `근무일` 집계에 포함됨이 확정(이전 대화에서 예고된 "다음 리비전" 결정이 v2에서 공식 반영됨).
- 다음 금지 문구 명문화: `자동 계산`, `읽기 전용`, `직접 조정`, `변경사항 저장`. `근무시간 조정` 개념 자체를 제거.

## 1. 프로젝트 개요

Personal Work OS는 개인의 계획·실행·근무기록·분석을 한곳에서 관리하는 데스크톱 웹앱이다.

현재 우선순위는 전체 앱을 한꺼번에 완성하는 것이 아니라, Work Log(근무 기록) 화면부터 실제로 사용할 수 있는 수준으로 완성하는 것이다.

현재 단계에서는 모바일 사용을 상정하지 않는다. 반응형 모바일 UI, Drawer 전환 등은 이번 작업 범위에서 제외하고 데스크톱 화면에 집중한다. (기본 지원 너비: 1280px 이상 권장, 1024px 이상에서 동작.)

## 2. 디자인 기준

전체 디자인 방향은 다음과 같다 (v1과 동일, v2에서도 유지):

- 기본 테마: GitHub Light
- 흰색·아주 옅은 회색 중심의 평평한 화면
- 얇은 회색 테두리와 격자로 영역 구분
- 그림자, 그라데이션, 발광 효과 최소화
- 파란색은 선택·포커스·링크에 제한적으로 사용
- 초록색은 근무 상태나 저장 버튼 등 긍정적 의미에 사용
- 상태값은 GitHub Label과 유사한 배지 형태
- 둥근 모서리는 과도하게 사용하지 않음
- 운영 도구처럼 정보 밀도가 높고 정돈된 데스크톱 UI
- 테이블은 모든 열의 세로·가로 격자가 명확하게 보여야 함

기존의 일반적인 다크 SaaS 관리자 화면 느낌은 사용하지 않는다. 별도 요청이 없다면 앞으로 Personal Work OS의 모든 화면은 GitHub Light를 기본 기준으로 잡는다.

## 3. 전체 화면 구조 (v2)

Work Log 화면은 다음 영역으로 구성한다.

1. 왼쪽 전역 사이드바 (변경 없음)
2. **페이지 타이틀 없음** — 사이드바의 "근무 기록" 활성 항목이 내비게이션 컨텍스트를 제공
3. 상단 개요 영역: 좌측 월간 출결 도넛 + 우측 오늘의 근무 패널, 그 아래 가로형 오늘의 근무 요약 패널
4. 기간 도구 영역 (주/월 탭, 기간 이동, 검색·필터·열 설정)
5. 중앙 근무 기록 테이블 (주간 뷰) 또는 주 단위로 그룹화된 테이블 블록 (월간 뷰)
6. 하단 기간 요약
7. 근무 추이 차트 2종
8. **상시 우측 상세 패널 없음** — 행 클릭 시 `근무 기록 상세` 모달이 뜬다

본문 영역은 사이드바를 제외한 가용 뷰포트 안에서 적정 최대 너비로 **중앙 정렬**하고 좌우에 균형 잡힌 여백을 둔다. 우측 상시 패널이 사라졌다고 해서 본문을 뷰포트 끝까지 늘리지 않는다.

## 4. 사이드바 용어

(변경 없음)

사이드바 메뉴는 다음과 같이 한국어로 표시한다.

- Dashboard → 대시보드
- Planning → 계획
- Execution → 실행
- Review → 회고
- Work Log → 근무 기록
- Analytics → 분석
- Settings → 설정

현재 선택된 `근무 기록` 메뉴는 활성 상태가 명확하게 보여야 한다.

제품명 `Personal Work OS`는 영문을 유지한다.

## 5. 기간 도구 영역 (v2 개정)

기간 단위는 다음 **두 개만** 구현한다:

- Week → 주
- Month → 월

`사용자 지정`(Custom)은 이번 범위에서 구현하지 않는다 — 이미지에 우연히 포함되어 있더라도 구현하지 않는다.

주간 이동 용어:

- Previous week → 저번 주
- Today → 오늘
- Next week → 다음 주

월간 이동도 동일한 패턴(`저번 달` / `다음 달`)을 따른다.

그 밖의 도구:

- Search → 검색
- Filter → 필터
- Columns → 열 설정

날짜 범위는 `2026.08.10–2026.08.16`처럼 숫자 중심으로 간결하게 표시한다.

## 6. 상단 개요 영역 (v2 신설)

기간 도구 영역과 별개로, 화면 최상단에 다음 세 요소로 구성된 개요 영역을 둔다. 이 영역은 주간 뷰와 월간 뷰 모두에서 동일하게 노출된다(뷰 전환과 무관하게 항상 표시).

### 6.1 월간 출결 도넛

해당 월의 출결 현황을 도넛 차트로 표시한다. 범례는 다음 6개 항목을 사용한다:

- 근무
- 조퇴
- 휴일
- 연차
- 병가
- 미입력

도넛 중앙에는 근무일 합계(예: `15일 근무일`)와 진행 정보(예: `20일 경과 / 31일`)를 표시한다.

규칙:

- **미래 날짜는 `미입력`으로 집계하지 않는다.** `미입력`은 이미 지난 날짜인데 기록이 없는 경우에만 집계한다.
- `근무일` 카운트는 `근무`와 `조퇴`를 모두 포함한다.

### 6.2 오늘의 근무 패널

포함 항목:

- 날짜
- 출결
- 근무 장소
- 출근 시간
- 퇴근 시간
- `출근` 버튼
- `퇴근` 버튼

규칙:

- 기본 표시 근무 장소: `카프카 사무실`
- 출퇴근 시각은 12시간 AM/PM 표기를 사용한다 (예: `09:12 AM`, `06:02 PM`)
- 기간 합계 등 지속시간 값은 계속 `HH:MM` 표기를 사용한다 (AM/PM 대상 아님)
- `출근`은 유일하게 파란색으로 채워진(filled) 액션 버튼이다
- `퇴근`은 옅은 붉은색(pale red) 경고 톤을 사용한다
- 그 외 액션 버튼은 중립적인 아웃라인 스타일을 사용한다
- 상태 배지는 절제된 시맨틱 색상을 유지한다

### 6.3 오늘의 근무 요약

다음 항목을 가로로 나열한다:

`출결 | 체류 시간 | 실근무 | 작업 블록 합계 | 지각 | 근무 점수 | 메모`

액션:

- `업무시간 기록` — §10 업무시간 기록 모달의 1차 진입점
- `저장`

**다음 문구는 어디에서도 사용하지 않는다**: `자동 계산`, `읽기 전용`, `직접 조정`, `변경사항 저장`.

이전에 있었던 "근무시간 조정" 개념은 제거한다. `실근무`는 오늘의 근무 요약에서 독립적으로 편집하지 않는다 — 그 값은 §10 업무시간 기록 모달에 기록된 항목별 시간의 합으로 산출된다.

## 7. 주간 테이블 확정 구조 (v2 개정)

테이블 열은 다음 순서로 고정한다.

`요일 | 날짜 | 출결 | 출퇴근 | 지각 | 체류 시간 | 실근무 | 점수 | 메모`

**v1과의 차이**: `지각`이 `출퇴근` 다음에 독립된 열로 추가되었다. `출퇴근` 열 안에는 더 이상 지각 문구를 반복하지 않는다.

### 요일

(변경 없음) 요일은 테이블의 가장 왼쪽에 독립된 열로 두고, 한국어 전체 요일명(월요일~일요일)을 사용한다. 요일과 날짜를 한 셀에 합치지 않는다.

### 출결

(변경 없음) 상태값은 다음 5개만 사용한다: `근무`, `휴일`, `연차`, `병가`, `조퇴`. `Day Off`는 반드시 `휴일`로 표시한다. 색상이 절제된 작은 배지로 보여준다.

### 출퇴근

출근 시간과 퇴근 시간을 하나의 열로 합친다. **12시간 AM/PM 표기를 사용한다.**

기본 표시 (v2):

`09:12 AM–06:02 PM`

지각 여부는 이 열에 표시하지 않는다 — 아래 `지각` 전용 열을 사용한다.

### 지각 (v2 신설 컬럼)

`출퇴근` 바로 오른쪽에 위치하는 독립 열이다. 값은 다음 세 가지 형태 중 하나다:

- `정시 출근` (지각 아님)
- `{n}분 지각` (지각한 분만큼)
- `-` (출퇴근 기록이 없는 날, 예: 휴일/연차/병가)

정확한 지각 판정 임계값은 유예됨 — §17 참조.

### 체류 시간

(변경 없음) `Basic Work`의 최종 한국어 명칭. 출근 시간부터 퇴근 시간까지 기준 자동 계산값. 단, 이 필드를 설명할 때 "자동 계산"이라는 문구 자체는 UI에 노출하지 않는다(§6.3 금지 문구 참조 — 값 자체는 계속 자동 산출되지만 라벨/힌트 텍스트로 그 단어를 쓰지 않는다는 뜻).

### 실근무

(개정) `Net Work`의 최종 한국어 명칭. **더 이상 사용자가 이 필드를 직접 조정하지 않는다.** §10 업무시간 기록 모달에 기록된 항목별 시간의 합으로 산출된다. 테이블에서는 `체류 시간` 바로 오른쪽에 배치한다.

### 작업 블록 합계

(변경 없음) Planning/Execution에서 기록된 실제 작업 블록의 합산값, 읽기 전용. 중앙 테이블에는 표시하지 않는다 — 상세 모달과 기간 요약에서만 표시한다.

### 점수

(변경 없음) 100점 만점, 숫자만 표시 + 원형 진행 링. `/ 100` 표기 금지, 별 아이콘 금지.

### 메모

(변경 없음) 테이블에서는 한 줄 미리보기만 표시, 길면 잘라서 표시. 전체 확인·수정은 상세 모달에서.

## 8. 근무 장소

근무 장소는 중앙 테이블에서 완전히 제외한다. 근무 장소는 오늘의 근무 패널과 상세 모달에서만 확인·수정한다.

**기본 표시 근무 장소 (v2): `카프카 사무실`** (v1의 `다올 사무실`에서 변경됨).

`Office`나 다른 임의 표현은 사용하지 않는다. 내부 DB 값은 기존 영문 코드 등을 유지해도 무방하지만, 사용자 화면에는 `카프카 사무실`로 표시한다.

## 9. 근무 기록 상세 모달 (v2 — 상시 패널에서 모달로 전환)

주간 테이블 또는 월간 테이블의 행을 클릭하면, **상시 패널이 아니라 모달**이 열린다.

모달 이름: `근무 기록 상세`

모달은 **조회(읽기) 모드로 열린다.** 표시 항목:

- 날짜
- 출결
- 근무 장소
- 출근 시간
- 퇴근 시간
- 체류 시간
- 실근무
- 작업 블록 합계
- 지각
- 근무 점수
- 메모

푸터 액션:

- `닫기`
- `수정`

**편집은 `수정`을 누른 뒤에만 가능하다.** 조회 모드에서는 모든 필드가 읽기 전용으로 보여야 한다(출결도 배지로만 표시, select 아님).

모달에는 추가로 `업무시간 기록 보기` 액션이 있다. 이 액션은 **근무 기록 상세 모달을 업무시간 기록 모달로 교체**한다 — 두 모달을 동시에 쌓지(stack) 않는다.

## 10. 업무시간 기록 모달 (v2 신설)

모달 이름: `업무시간 기록`

진입점:

- 1차: 오늘의 근무 요약의 `업무시간 기록` 버튼
- 2차: 근무 기록 상세 모달의 `업무시간 기록 보기` 액션

이것은 **가산형(additive) 시간 기록 모델**이지, 시간 배분(allocation) 모델이 아니다.

열 순서 고정: `항목 | 시간 | 메모 | 관리`

규칙:

- 사용자는 `HH:MM` 형식으로 시간을 직접 입력한다
- 항목의 예시 카테고리: 기획, 개발, 검수, 기록/정리, 공부 (예시일 뿐, 확정된 고정 목록이 아님)
- **모든 기록의 합이 그날의 `실근무`가 된다**
- 목표 시간, 배분 시간, 남은 시간, 미배분 시간, 진행률 개념을 사용하지 않는다
- 이 기능을 `시간 배분`이라고 부르지 않는다
- 개인 시간 탭을 추가하지 않는다
- 중복 카테고리에 대한 규칙은 아직 만들지 않는다 (§17 유예)

액션:

- `기록 추가`
- `취소`
- `저장`

## 11. 기간 요약

### 11.1 주간 요약

주간 뷰에서는 다음 5개 항목을 표시한다:

- 체류 시간 합계
- 실근무 합계
- 작업 블록 합계
- 평균 점수
- 근무일

`작업 블록 합계`는 테이블에서는 제외하지만 요약에서는 유지한다. 평균 점수는 숫자와 원형 진행 링으로 표시한다. `근무일`은 `근무`+`조퇴`를 합산한다.

### 11.2 월간 요약 (v2 신설)

월간 뷰에서는 주간과 **다른 4개 항목**을 표시한다:

- 실근무 합계
- 근무일 평균 (근무일 1일당 평균 실근무 시간)
- 평균 점수
- 근무일

## 12. 근무 추이 차트 (v2 신설)

Work Log 페이지에는 다음 두 개의 맥락 차트만 둔다:

- 주간 실근무 시간
- 주간 평균 점수

체크리스트 관련 기능/차트는 Work Log에서 제외한다 (추후 Review 또는 Analytics에서 재검토 가능).

스타일 규칙:

- 각진 폴리라인이 아니라 **부드러운 monotone 곡선** 사용
- 데이터 포인트를 시각적으로 표시
- 값 라벨은 컴팩트하게 표시
- 영역 채우기는 **아주 옅게(very pale)**
- GitHub Light의 절제된 색상 사용

주간 뷰에서는 최근 3주가, 월간 뷰에서는 해당 월의 주 수만큼(예: 4~5개) 데이터 포인트로 표시된다.

## 13. 월간 뷰 (v2 신설)

월간 뷰는 해당 월의 일별 기록을 **주 단위로 그룹화**하여 보여준다.

요구사항:

- 각 주는 별도의 테두리를 가진 테이블 블록이다
- 주 블록 사이에는 약 18–24px의 세로 간격을 둔다
- 각 주 블록마다 테이블 헤더를 반복한다
- 각 주 헤더는 해당 주의 날짜 범위와 간단한 주간 요약(예: `실근무 36:35 · 평균 점수 85 · 근무일 5일`)을 함께 보여준다
- 행 클릭 시 주간 뷰와 동일한 `근무 기록 상세` 모달이 열린다
- 상시 우측 패널을 렌더링하지 않는다
- 컬럼 순서와 용어는 주간 뷰와 동일하게 유지한다 (§7)

## 14. 기본 상호작용 (v2 개정)

- 행 클릭 → **모달**로 `근무 기록 상세`가 열림 (v1: 우측 패널 갱신 → v2: 모달)
- 선택 행 → 강한 파란 면이 아니라 옅은 파란 배경과 좁은 강조선 사용
- 출결 배지 → 상태에 맞는 절제된 색상 사용
- 검색 → 현재 근무 기록 검색
- 필터 → 출결이나 기간 조건 필터링
- 열 설정 → 향후 표시 열을 조절할 수 있는 진입점
- 상세 모달의 `닫기` → 모달을 닫음
- 상세 모달의 `수정` → 조회 모드에서 편집 모드로 전환
- 상세 모달의 `업무시간 기록 보기` → 상세 모달을 업무시간 기록 모달로 교체 (스택 금지)
- 업무시간 기록 모달의 `기록 추가` → 새 항목 행 추가
- 업무시간 기록 모달의 `취소` → 편집 내용 폐기
- 업무시간 기록 모달의 `저장` → 항목 저장, 합계가 `실근무`에 반영
- 하단 요약 → 현재 조회 기간을 기준으로 계산

## 15. 구현 시 반드시 지킬 사항 (v2 개정)

- 첨부된 확정 이미지를 임의로 재해석하거나 전면 재설계하지 않는다.
- **이미지에 우연히 포함된 텍스트/데이터 불일치보다 이 문서의 명문화된 요구사항이 우선한다.**
- 모바일 UI는 현재 구현 범위에서 제외한다.
- GitHub Light 스타일을 유지한다.
- 테이블 열 순서와 용어를 임의로 변경하지 않는다.
- 근무 장소를 테이블에 다시 추가하지 않는다.
- 작업 블록 합계를 테이블 열로 추가하지 않는다.
- 점수에 `/ 100`을 표시하지 않는다.
- 요일을 날짜와 합치거나 영문 축약형으로 바꾸지 않는다.
- 출결 상태값을 확정된 5개 외에 임의로 추가하지 않는다.
- 한국어 UI 안에 불필요한 영문 라벨을 혼용하지 않는다.
- **다음 문구를 어디에도 사용하지 않는다: `자동 계산`, `읽기 전용`, `직접 조정`, `변경사항 저장`.**
- **`근무시간 조정` 개념을 다시 도입하지 않는다.**
- **`사용자 지정` 기간 단위를 구현하지 않는다.**
- **근무 기록 상세 모달과 업무시간 기록 모달을 동시에 쌓지(stack) 않는다.**
- **업무시간 기록에 목표/배분/잔여/미배분/진행률 개념을 도입하지 않는다. `시간 배분`이라는 이름을 쓰지 않는다. 개인 시간 탭을 추가하지 않는다.**
- 기존 기능이나 데이터 구조를 변경해야 한다면 먼저 현재 코드와 스키마를 확인하고 영향 범위를 보고한다.
- 한 번에 큰 범위를 수정하기보다 작은 안정 단위로 구현하고 검증한다.

## 16. 현재 확정 상태와 다음 작업

Work Log의 v2 화면 디자인과 사용자 노출 용어는 확정되었다. 아직 어떤 구현 코드도 v2에 맞춰 수정되지 않았다 (Phase 2 초안은 v1 기준으로 구현됨 — 갭 분석은 별도 보고서 참조).

다음 단계에서는 이 명세를 기준으로 작은 단위의 구현 커밋을 순서대로 진행한다 (제안된 커밋 순서는 갭 분석 보고서 참조).

## 17. 유예된 비즈니스 규칙 (구현 차단 요소 아님)

다음 항목은 아직 확정되지 않았다. 정적 UI와 상호작용 구현을 진행하되, 아래 값을 임의로 발명하거나 하드코딩하지 않고 이후 데이터 통합 단계에서 정의한다:

- **정확한 지각 임계값과 유예 시간(grace period).** 추후 Planning의 계획 출근 시간(planned start time) + 설정 가능한 유예 시간(grace period)을 기준으로 계산될 예정이다. 지금 단계에서 유예 시간이나 고정된 계획 출근 시간을 하드코딩하지 않는다.
- 조퇴 판정의 정확한 계산 규칙
- 지각 또는 조퇴가 근무 점수에 영향을 주는지 여부
- 업무시간 기록에서 중복 카테고리를 어떻게 처리할지

지각·조퇴의 UI상 위치와 라벨은 이미 확정되어 있다(§7 `지각` 컬럼, §6.2/§6.3/§9의 `지각` 필드). 유예되는 것은 오직 그 값을 계산·집계하는 로직뿐이다.

**이미 확정된 것 (더 이상 유예 아님)**: `근무일` 집계는 `근무`와 `조퇴`를 모두 포함한다. 출결 배지 색상 매핑은 다음 UI 다듬기 패스에서 재검토 예정(별도 결정 대기 중, 이 문서의 색상 관련 내용은 §2의 일반 원칙 수준으로만 유지).
