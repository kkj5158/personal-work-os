## 0. v1 → v2 변경 이력

- 화면 상단의 "근무 기록" 페이지 타이틀 제거 — 전역 사이드바가 이미 내비게이션 컨텍스트를 제공하므로 중복.
- 본문 영역을 화면 전체에 늘려 채우지 않고, 적정 최대 너비로 중앙 정렬(좌우 여백 균형).
- 상시 노출되던 우측 상세 패널을 **완전히 제거**. 행 클릭 시 모달로 대체.
- 상단에 새로운 개요 영역 추가: (1) 월간 출결 도넛 차트, (2) 오늘의 근무 패널, (3) 오늘의 근무 요약 패널.
- 주간 테이블에 `지각` 전용 컬럼 추가, `출퇴근` 컬럼에서 지각 텍스트 중복 제거.
- 출퇴근 시간 표기를 24시간제에서 12시간 AM/PM 표기로 변경 (예: `09:12 AM`).
- 근무 장소 기본 표시값을 `다올 사무실`에서 `카프카 사무실`로 변경.
- `근무 기록 상세`가 상시 패널에서 **모달**로 전환, 조회 모드로 열리고 `수정` 버튼을 눌러야 편집 가능.
- `업무시간 기록` 모달 신설 — 가산형(additive) 시간 기록 모델. 항목별 기록의 합이 그날의 `실근무`가 됨.
- `기간 단위`에서 `사용자 지정` 제외 — `주`, `월`만 구현.
- 주간/월간 요약 아래에 근무 추이 차트 2종(`주간 실근무 시간`, `주간 평균 점수`) 추가.
- 월간 뷰 신설 — 주 단위로 그룹화된 블록.
- `조퇴`가 `근무일` 집계에 포함됨이 확정(이전 대화에서 예고된 "다음 리비전" 결정이 v2에서 공식 반영됨).
- 다음 금지 문구 명문화: `자동 계산`, `읽기 전용`, `직접 조정`, `변경사항 저장`. `근무시간 조정` 개념 자체를 제거.

## 1. 프로젝트 개요

Personal Work OS는 개인의 계획·실행·근무기록·분석을 한곳에서 관리하는 데스크톱 웹앱이다.

현재 우선순위는 전체 앱을 한꺼번에 완성하는 것이 아니라, Work Log(근무 기록) 화면부터 실제로 사용할 수 있는 수준으로 완성하는 것이다.

현재 단계에서는 모바일 사용을 상정하지 않는다. 반응형 모바일 UI, Drawer 전환 등은 이번 작업 범위에서 제외하고 데스크톱 화면에 집중한다. (기본 지원 너비: 1280px 이상 권장, 1024px 이상에서 동작.)

## 2. 디자인 기준

전체 디자인 방향은 다음과 같다 (v1과 동일, v2에서도 유지):

- 기본 테마: GitHub Light
- 흰색·아주 옅은 회색 중심의 평평한 화면
- 얇은 회색 테두리와 격자로 영역 구분
- 그림자, 그라데이션, 발광 효과 최소화
- 파란색은 선택·포커스·링크에 제한적으로 사용
- 초록색은 근무 상태나 저장 버튼 등 긍정적 의미에 사용
- 상태값은 GitHub Label과 유사한 배지 형태
- 둥근 모서리는 과도하게 사용하지 않음
- 운영 도구처럼 정보 밀도가 높고 정돈된 데스크톱 UI
- 테이블은 모든 열의 세로·가로 격자가 명확하게 보여야 함

기존의 일반적인 다크 SaaS 관리자 화면 느낌은 사용하지 않는다. 별도 요청이 없다면 앞으로 Personal Work OS의 모든 화면은 GitHub Light를 기본 기준으로 잡는다.

## 3. 전체 화면 구조 (v2)

Work Log 화면은 다음 영역으로 구성한다.

1. 왼쪽 전역 사이드바 (변경 없음)
2. **페이지 타이틀 없음** — 사이드바의 "근무 기록" 활성 항목이 내비게이션 컨텍스트를 제공
3. 상단 개요 영역: 좌측 월간 출결 도넛 + 우측 오늘의 근무 패널, 그 아래 가로형 오늘의 근무 요약 패널
4. 기간 도구 영역 (주/월 탭, 기간 이동, 검색·필터·열 설정)
5. 중앙 근무 기록 테이블 (주간 뷰) 또는 주 단위로 그룹화된 테이블 블록 (월간 뷰)
6. 하단 기간 요약
7. 근무 추이 차트 2종
8. **상시 우측 상세 패널 없음** — 행 클릭 시 `근무 기록 상세` 모달이 뜬다

본문 영역은 사이드바를 제외한 가용 뷰포트 안에서 적정 최대 너비로 **중앙 정렬**하고 좌우에 균형 잡힌 여백을 둔다. 우측 상시 패널이 사라졌다고 해서 본문을 뷰포트 끝까지 늘리지 않는다.

## 4. 사이드바 용어

(변경 없음)

사이드바 메뉴는 다음과 같이 한국어로 표시한다.

- Dashboard → 대시보드
- Planning → 계획
- Execution → 실행
- Review → 회고
- Work Log → 근무 기록
- Analytics → 분석
- Settings → 설정

현재 선택된 `근무 기록` 메뉴는 활성 상태가 명확하게 보여야 한다.

제품명 `Personal Work OS`는 영문을 유지한다.

## 5. 기간 도구 영역 (v2 개정)

기간 단위는 다음 **두 개만** 구현한다:

- Week → 주
- Month → 월

`사용자 지정`(Custom)은 이번 범위에서 구현하지 않는다 — 이미지에 우연히 포함되어 있더라도 구현하지 않는다.

주간 이동 용어:

- Previous week → 저번 주
- Today → 오늘
- Next week → 다음 주

월간 이동도 동일한 패턴(`저번 달` / `다음 달`)을 따른다.

그 밖의 도구:

- Search → 검색
- Filter → 필터
- Columns → 열 설정

날짜 범위는 `2026.08.10–2026.08.16`처럼 숫자 중심으로 간결하게 표시한다.

## 6. 상단 개요 영역 (v2 신설)

기간 도구 영역과 별개로, 화면 최상단에 다음 세 요소로 구성된 개요 영역을 둔다. 이 영역은 주간 뷰와 월간 뷰 모두에서 동일하게 노출된다(뷰 전환과 무관하게 항상 표시).

### 6.1 월간 출결 도넛

해당 월의 출결 현황을 도넛 차트로 표시한다. 범례는 다음 6개 항목을 사용한다:

- 근무
- 조퇴
- 휴일
- 연차
- 병가
- 미입력

도넛 중앙에는 근무일 합계(예: `15일 근무일`)와 진행 정보(예: `20일 경과 / 31일`)를 표시한다.

규칙:

- **미래 날짜는 `미입력`으로 집계하지 않는다.** `미입력`은 이미 지난 날짜인데 기록이 없는 경우에만 집계한다.
- `근무일` 카운트는 `근무`와 `조퇴`를 모두 포함한다.

### 6.2 오늘의 근무 패널

포함 항목:

- 날짜
- 출결
- 근무 장소
- 출근 시간
- 퇴근 시간
- `출근` 버튼
- `퇴근` 버튼

규칙:

- 기본 표시 근무 장소: `카프카 사무실`
- ~~출퇴근 시각은 12시간 AM/PM 표기를 사용한다~~ **(v7 정정: 24시간제 `HH:mm`로 확정, 예: `09:12`, `18:02` — §18 참고)**
- 기간 합계 등 지속시간 값은 계속 `HH:MM` 표기를 사용한다
- `출근`은 유일하게 파란색으로 채워진(filled) 액션 버튼이다
- `퇴근`은 옅은 붉은색(pale red) 경고 톤을 사용한다
- 그 외 액션 버튼은 중립적인 아웃라인 스타일을 사용한다
- 상태 배지는 절제된 시맨틱 색상을 유지한다

### 6.3 오늘의 근무 요약

다음 항목을 가로로 나열한다:

`출결 | 체류 시간 | 실근무 | 작업 블록 합계 | 지각 | 근무 점수 | 메모`

> **현재 상태 (v4)**: `작업 블록 합계`는 현재 오늘의 근무 요약을 포함한 Work Log 전 화면에서 표시하지 않는다 — 이 결정은 §11.1/§9의 동일 항목에도 적용된다. 기반 데이터(`actualBlockMinutes`)와 선택자는 그대로 보존되어 있다.

액션:

- `업무시간 기록` — §10 업무시간 기록 모달의 1차 진입점
- `저장`

**다음 문구는 어디에서도 사용하지 않는다**: `자동 계산`, `읽기 전용`, `직접 조정`, `변경사항 저장`.

이전에 있었던 "근무시간 조정" 개념은 제거한다. `실근무`는 오늘의 근무 요약에서 독립적으로 편집하지 않는다 — 그 값은 §10 업무시간 기록 모달에 기록된 항목별 시간의 합으로 산출된다.

## 7. 주간 테이블 확정 구조 (v2 개정)

테이블 열은 다음 순서로 고정한다.

`요일 | 날짜 | 출결 | 출퇴근 | 지각 | 체류 시간 | 실근무 | 점수 | 메모`

**v1과의 차이**: `지각`이 `출퇴근` 다음에 독립된 열로 추가되었다. `출퇴근` 열 안에는 더 이상 지각 문구를 반복하지 않는다.

### 요일

(변경 없음) 요일은 테이블의 가장 왼쪽에 독립된 열로 두고, 한국어 전체 요일명(월요일~일요일)을 사용한다. 요일과 날짜를 한 셀에 합치지 않는다.

### 출결

(변경 없음) 상태값은 다음 5개만 사용한다: `근무`, `휴일`, `연차`, `병가`, `조퇴`. `Day Off`는 반드시 `휴일`로 표시한다. 색상이 절제된 작은 배지로 보여준다.

### 출퇴근

출근 시간과 퇴근 시간을 하나의 열로 합친다.

**(v7 정정)** 24시간제 `HH:mm`를 사용한다:

`09:12–18:02`

지각 여부는 이 열에 표시하지 않는다 — 아래 `지각` 전용 열을 사용한다.

### 지각 (v2 신설 컬럼)

`출퇴근` 바로 오른쪽에 위치하는 독립 열이다. 값은 다음 세 가지 형태 중 하나다:

- `정시 출근` (지각 아님)
- `{n}분 지각` (지각한 분만큼)
- `-` (출퇴근 기록이 없는 날, 예: 휴일/연차/병가)

정확한 지각 판정 임계값은 유예됨 — §17 참조.

### 체류 시간

(변경 없음) `Basic Work`의 최종 한국어 명칭. 출근 시간부터 퇴근 시간까지 기준 자동 계산값. 단, 이 필드를 설명할 때 "자동 계산"이라는 문구 자체는 UI에 노출하지 않는다(§6.3 금지 문구 참조 — 값 자체는 계속 자동 산출되지만 라벨/힌트 텍스트로 그 단어를 쓰지 않는다는 뜻).

### 실근무

(개정) `Net Work`의 최종 한국어 명칭. **더 이상 사용자가 이 필드를 직접 조정하지 않는다.** §10 업무시간 기록 모달에 기록된 항목별 시간의 합으로 산출된다. 테이블에서는 `체류 시간` 바로 오른쪽에 배치한다.

### 작업 블록 합계

(변경 없음) Planning/Execution에서 기록된 실제 작업 블록의 합산값, 읽기 전용.

> **현재 상태 (v4)**: 상세 모달·기간 요약을 포함해 현재 어떤 Work Log 화면에도 표시하지 않는다 — 위 "중앙 테이블에는 표시하지 않는다"는 문구는 더 이상 유일한 예외 조건이 아니다. 데이터/선택자 자체는 보존.

### 점수

100점 만점, 숫자만 표시. `/ 100` 표기 금지, 별 아이콘 금지. ~~원형 진행 링~~ **(v7 정정: 사용하지 않음 — 어떤 Work Log 화면에도 ScoreRing을 두지 않는다)**.

### 메모

(변경 없음) 테이블에서는 한 줄 미리보기만 표시, 길면 잘라서 표시. 전체 확인·수정은 상세 모달에서.

## 8. 근무 장소

근무 장소는 중앙 테이블에서 완전히 제외한다. 근무 장소는 오늘의 근무 패널과 상세 모달에서만 확인·수정한다.

**기본 표시 근무 장소 (v2): `카프카 사무실`** (v1의 `다올 사무실`에서 변경됨).

`Office`나 다른 임의 표현은 사용하지 않는다. 내부 DB 값은 기존 영문 코드 등을 유지해도 무방하지만, 사용자 화면에는 `카프카 사무실`로 표시한다.

## 9. 근무 기록 상세 모달 (v2 — 상시 패널에서 모달로 전환)

주간 테이블 또는 월간 테이블의 행을 클릭하면, **상시 패널이 아니라 모달**이 열린다.

모달 이름 (v7 정정): `근무 기록 수정`

> **(v7 정정)** ~~모달은 조회(읽기) 모드로 열리고 `수정`을 눌러야 편집 가능~~ — 이 흐름은 더 이상 유효하지 않다. 행을 클릭하면 **곧바로 편집 가능한 통합 폼**이 열린다. 조회 전용 모드, `수정`/`닫기` 버튼은 존재하지 않는다. 푸터는 `취소`/`저장`뿐이다. 업무시간 기록 편집기는 이 모달 안에 **임베드**되어 있다 — `업무시간 기록 보기`로 별도 모달을 여는 흐름은 폐기되었다. 전체 사양은 §18 참고.

## 10. 업무시간 기록 모달 (v2 신설)

모달 이름: `업무시간 기록`

> **(v7 정정)** 이 "2차 진입점"(상세 모달 → 업무시간 기록 모달로 교체)은 더 이상 존재하지 않는다 — 통합 레코드 수정 모달은 같은 편집기를 **임베드**해서 보여준다(§9). 이 독립 모달은 이제 **오늘의 근무 요약 전용**(1차 진입점)으로만 열리며, 향후 `일` 뷰가 도입되면 대체될 임시 화면이다(§18).

진입점 (현재):

- 오늘의 근무 요약의 `업무시간 기록` 버튼 (임시 — §18의 유예 항목 참고)

이것은 **가산형(additive) 시간 기록 모델**이지, 시간 배분(allocation) 모델이 아니다.

열 순서 고정 (v9 정정): `카테고리 | 항목 | 시간 | 메모 | 관리` — 카테고리 열이 신설되어 항목보다 앞에 온다. 상세는 §18.7 참고.

규칙:

- 사용자는 `HH:MM` 형식으로 시간을 직접 입력한다
- 항목의 예시 카테고리: 기획, 개발, 검수, 기록/정리, 공부 (예시일 뿐, 확정된 고정 목록이 아님)
- **모든 기록의 합이 그날의 `실근무`가 된다**
- 목표 시간, 배분 시간, 남은 시간, 미배분 시간, 진행률 개념을 사용하지 않는다
- 이 기능을 `시간 배분`이라고 부르지 않는다
- 개인 시간 탭을 추가하지 않는다
- 중복 카테고리에 대한 규칙은 아직 만들지 않는다 (§17 유예)

액션:

- `기록 추가`
- `취소`
- `저장`

## 11. 기간 요약

주간 뷰에서는 다음 5개 항목을 표시한다:

## 12. 근무 추이 차트 (v2 신설)

Work Log 페이지에는 다음 두 개의 맥락 차트만 둔다:

- 주간 실근무 시간
- 주간 평균 점수

체크리스트 관련 기능/차트는 Work Log에서 제외한다 (추후 Review 또는 Analytics에서 재검토 가능).

스타일 규칙:

- 각진 폴리라인이 아니라 **부드러운 monotone 곡선** 사용
- 데이터 포인트를 시각적으로 표시
- 값 라벨은 컴팩트하게 표시
- 영역 채우기는 **아주 옅게(very pale)**
- GitHub Light의 절제된 색상 사용

주간 뷰에서는 최근 3주가, 월간 뷰에서는 해당 월의 주 수만큼(예: 4~5개) 데이터 포인트로 표시된다.

## 13. 월간 뷰 (v2 신설)

월간 뷰는 해당 월의 일별 기록을 **주 단위로 그룹화**하여 보여준다.

요구사항:

- 각 주는 별도의 테두리를 가진 테이블 블록이다
- 주 블록 사이에는 약 18–24px의 세로 간격을 둔다
- 각 주 블록마다 테이블 헤더를 반복한다
- 각 주 헤더는 해당 주의 날짜 범위와 간단한 주간 요약(예: `실근무 36:35 · 평균 점수 85 · 근무일 5일`)을 함께 보여준다
- 행 클릭 시 주간 뷰와 동일한 `근무 기록 상세` 모달이 열린다
- 상시 우측 패널을 렌더링하지 않는다
- 컬럼 순서와 용어는 주간 뷰와 동일하게 유지한다 (§7)

## 14. 기본 상호작용 (v2 개정)

- 행 클릭 → **모달**로 `근무 기록 수정`이 곧바로 편집 가능한 상태로 열림 (v7: 조회 모드 없음 — §9/§18)
- 선택 행 → 강한 파란 면이 아니라 옅은 파란 배경과 좁은 강조선 사용
- 출결 → 상태색 텍스트만 사용, 배지/필/점 없음 (v7 정정 — §18)
- ~~검색/필터/열 설정~~ **(v7 정정: 제거됨 — §18)**
- 레코드 수정 모달의 `취소` → 편집 내용(업무시간 기록 포함) 전체 폐기
- 레코드 수정 모달의 `저장` → 전체 draft 저장, 실근무는 업무시간 기록 합계로 반영
- 레코드 수정 모달 안의 `기록 추가` → 임베드된 업무시간 편집기에 새 항목 행 추가
- 하단 요약 → 현재 조회 기간을 기준으로 계산

## 15. 구현 시 반드시 지킬 사항 (v2 개정)

- 첨부된 확정 이미지를 임의로 재해석하거나 전면 재설계하지 않는다.
- **이미지에 우연히 포함된 텍스트/데이터 불일치보다 이 문서의 명문화된 요구사항이 우선한다.**
- 모바일 UI는 현재 구현 범위에서 제외한다.
- GitHub Light 스타일을 유지한다.
- 테이블 열 순서와 용어를 임의로 변경하지 않는다.
- 근무 장소를 테이블에 다시 추가하지 않는다.
- 작업 블록 합계를 테이블 열로 추가하지 않는다.
- 점수에 `/ 100`을 표시하지 않는다.
- 요일을 날짜와 합치거나 영문 축약형으로 바꾸지 않는다.
- 출결 상태값을 확정된 5개 외에 임의로 추가하지 않는다.
- 한국어 UI 안에 불필요한 영문 라벨을 혼용하지 않는다.
- **다음 문구를 어디에도 사용하지 않는다: `자동 계산`, `읽기 전용`, `직접 조정`, `변경사항 저장`.**
- **`근무시간 조정` 개념을 다시 도입하지 않는다.**
- **`사용자 지정` 기간 단위를 구현하지 않는다.**
- **Work Log 모달은 항상 하나만 떠 있어야 한다(stack 금지)** — 레코드 수정 모달은 업무시간 편집기를 임베드하며, 출근 취소/기록 삭제 확인도 같은 모달 안의 내부 상태 전환으로 처리한다(별도 모달을 새로 열지 않는다). §18 참고.
- **업무시간 기록에 목표/배분/잔여/미배분/진행률 개념을 도입하지 않는다. `시간 배분`이라는 이름을 쓰지 않는다. 개인 시간 탭을 추가하지 않는다.**
- 기존 기능이나 데이터 구조를 변경해야 한다면 먼저 현재 코드와 스키마를 확인하고 영향 범위를 보고한다.
- 한 번에 큰 범위를 수정하기보다 작은 안정 단위로 구현하고 검증한다.

## 16. 현재 확정 상태와 다음 작업

Work Log의 v2 화면 디자인과 사용자 노출 용어는 확정되었다. 아직 어떤 구현 코드도 v2에 맞춰 수정되지 않았다 (Phase 2 초안은 v1 기준으로 구현됨 — 갭 분석은 별도 보고서 참조).

다음 단계에서는 이 명세를 기준으로 작은 단위의 구현 커밋을 순서대로 진행한다 (제안된 커밋 순서는 갭 분석 보고서 참조).

## 17. 유예된 비즈니스 규칙 (구현 차단 요소 아님)

다음 항목은 아직 확정되지 않았다. 정적 UI와 상호작용 구현을 진행하되, 아래 값을 임의로 발명하거나 하드코딩하지 않고 이후 데이터 통합 단계에서 정의한다:

- **정확한 지각 임계값과 유예 시간(grace period).** 추후 Planning의 계획 출근 시간(planned start time) + 설정 가능한 유예 시간(grace period)을 기준으로 계산될 예정이다. 지금 단계에서 유예 시간이나 고정된 계획 출근 시간을 하드코딩하지 않는다.
- 조퇴 판정의 정확한 계산 규칙
- 지각 또는 조퇴가 근무 점수에 영향을 주는지 여부
- 업무시간 기록에서 중복 카테고리를 어떻게 처리할지

지각·조퇴의 UI상 위치와 라벨은 이미 확정되어 있다(§7 `지각` 컬럼, §6.2/§6.3/§9의 `지각` 필드). 유예되는 것은 오직 그 값을 계산·집계하는 로직뿐이다.

**이미 확정된 것 (더 이상 유예 아님)**: `근무일` 집계는 `근무`와 `조퇴`를 모두 포함한다.

## 18. v7 확정 구현 사양 (현재 소스 오브 트루스)

이 절은 이후 여러 UI 다듬기·정책 패스를 거쳐 실제로 구현·검증된 현재 동작을 요약한다. **위 §1–§17과 충돌하는 내용이 있으면 이 절이 우선한다.**

### 18.1 시간 표기·입력

- Work Log 전 화면 24시간제 `HH:mm` (예: `09:12–18:02`). 12시간 AM/PM 표기는 어디에도 없다.
- 모든 시간 입력은 재사용 가능한 `TimeInput`(네이티브 `input[type=time]`, `step=60`, 1분 단위) 또는 오늘 카드 전용 직접 클릭형 시간 컨트롤을 사용한다 — 연필 아이콘이나 확장형 확인/취소 입력행은 없다.
- 출근 시간이 퇴근 시간보다 늦으면(예: 19:00→01:00) 다음 날로 해석해 체류 시간을 계산한다(익일 근무). 출근=퇴근 동일 시각은 항상 무효.

### 18.2 오늘의 근무 — 출퇴근 상태 머신

| 상태 | 출근 | 퇴근 |
|---|---|---|
| 비근무 출결 | 비활성 | 비활성 |
| 출근 전 | 활성(저장된 활성 출근 기준 선택 시에만) | 비활성 |
| 출근함·퇴근 전 | `출근 취소`로 교체, 활성 | 활성 |
| 퇴근함 | 비활성 | 비활성 |

`출근 취소`는 확인 전용 모달(`출근을 취소할까요?` / `돌아가기` / `출근 취소`)을 거쳐 즉시 반영되며, 별도 저장 버튼이 필요 없다. 업무시간 기록이 하나라도 있으면 취소 자체가 차단되고 `업무시간 기록을 먼저 삭제해주세요.` / `확인` 모달만 뜬다. 완료된(퇴근까지 끝난) 오늘 레코드는 오늘 카드에서 취소/삭제할 수 없다 — 과거·완료 기록 정정은 통합 레코드 수정 모달에서만 한다(18.4).

### 18.3 저장된 출근 기준 정책

- 사용자가 새로 지정할 수 있는 적용 출근 기준은 **활성 저장 기준뿐**이다. `미설정`, `직접 입력`, 자유 시간 입력은 UI 어디에도 없다.
- 값이 없거나 더 이상 유효하지 않은 기준(과거 커스텀 스냅샷 포함)이면 트리거에 비선택 placeholder `출근 기준 선택`을 보여준다. 저장된 활성 기준이 하나도 없으면 `등록된 출근 기준 없음`을 보여준다.
- 근무/조퇴 레코드는 유효한 저장 기준이 선택되어야 신규 출근·레코드 저장이 가능하다(`출근 기준을 선택해주세요.`). 이미 출근한 진행 중 근무의 퇴근은 막지 않는다.
- 자동으로 아무 기준이나 대입하지 않는다. 기존 mock 데이터의 커스텀 스냅샷은 전부 `null`로 초기화되어 있다(생성 로직 자체가 더 이상 `custom` 소스를 만들지 않음).
- 적용 출근 기준 선택은 오늘 카드와 통합 레코드 수정 모달 모두 동일한 커스텀 리스트박스(이름 좌측/시간 우측, 활성 기준만)를 공유한다.

### 18.4 통합 레코드 수정 모달 (`근무 기록 수정`)

- 주간/월간 테이블 행 클릭 시 조회 모드 없이 곧바로 편집 폼이 열린다. 푸터는 `취소`/`저장`뿐.
- 출결, 출근/퇴근 시간, 적용 출근 기준, 정시 출근 처리 여부, 근무 점수, 업무시간 기록, 메모가 **하나의 draft**로 통합된다. `취소`/Escape/오버레이 클릭은 draft 전체를 폐기하고, `저장`만 전체를 한 번에 커밋한다.
- 업무시간 편집기(`WorkTimeEntryEditor`)가 모달 안에 **임베드**되어 있다 — 별도 모달(`업무시간 기록 보기`)로 전환하지 않는다.
- **출근/퇴근 기록 정정**: 출근만 있고 퇴근이 비어 있으면 `출근 취소` 버튼을, 둘 다 있으면 `출퇴근 기록 삭제` 버튼을 출근/퇴근 시간 필드 근처에 작은 아웃라인 danger 버튼으로 보여준다. 둘 다 비어 있으면 버튼이 없다.
- 확인은 **같은 모달 내부 상태 전환**으로 처리한다(두 번째 모달을 띄우지 않음) — 제목만 있는 확인 화면(`출근을 취소할까요?`/`출퇴근 기록을 삭제할까요?` + `돌아가기` + 파괴적 액션)으로 모달 내용이 일시적으로 바뀐다. 업무시간 기록이 남아있으면 같은 방식으로 `업무시간 기록을 먼저 삭제해주세요.` / `확인` 차단 화면이 뜬다. 두 경우 모두 `돌아가기`/`확인`/Escape/오버레이는 draft를 바꾸지 않고 편집 화면으로 되돌아간다.
- 확정 시 draft의 출근/퇴근 시간과 `isOnTimeOverride`만 초기화한다 — 출결/근무 장소/적용 기준/점수/메모/업무시간 기록은 그대로 유지되며, **이 시점엔 아직 저장되지 않는다**(모달의 `저장`을 눌러야 실제 반영). 비워진 시간 필드는 계속 클릭 가능한 `TimeInput`으로 남아 새 시간을 다시 입력할 수 있다.

### 18.5 정시 출근 처리 (온타임 오버라이드)

- 원본 지각은 항상 출근 시간과 적용된 저장 기준 스냅샷만으로 계산되며 절대 덮어쓰지 않는다.
- `정시 출근 처리`는 근무/조퇴 + 출근시간 존재 + 저장 기준 존재 + 원본 지각>0 + 미적용 상태일 때만 노출된다. 적용하면 `정시 출근`과 `처리 취소`로 바뀐다.
- 출근 시간 변경, 적용 기준 변경, 비근무 출결로 전환, 출근 취소/기록 삭제 시 자동으로 해제된다. 퇴근 시간·점수·메모·업무시간 기록 변경은 해제하지 않는다.
- 향후 공식 근태 예외/승인 워크플로가 이를 대체하기 전까지의 프런트엔드 전용 MVP다 — 백엔드 영속화·API 계약은 아직 없다(§18.8 유예 항목).

### 18.6 출결 표현·테이블·요약

- 출결은 상태색 텍스트만 사용한다(점·배지·필·테두리 없음). 편집 가능한 곳은 동일한 색상 텍스트 + 중립 셰브런의 커스텀 리스트박스(활성 순서: 근무/휴일/연차/병가/조퇴, `미입력` 없음).
- 도넛 범례는 예외적으로 색상 스와치(점)를 유지한다 — 이 정리 대상이 아니다.
- 주간/월간 테이블: 내부 세로 격자선 제거(외곽 테두리·가로 구분선·행 hover만 유지), 체류 시간·실근무는 중립 강조색(파랑/초록 장식 제거), 지각만 의미색 유지, `10+`는 정확한 값을 hover/focus 툴팁으로 노출. 검색/필터/열 설정 없음, 페이지네이션 없음.
- 오늘의 근무 요약: 상단 4열(출결/체류 시간/실근무/지각, 근무 점수 제외) + 하단 편집행(근무 점수/메모/업무시간 기록/저장). 점수 입력은 네이티브 스피너 숨김. `작업 블록 합계`와 ScoreRing은 Work Log 어디에도 없다.
- 근무 추이 차트 2종은 세로로 쌓인 전체 폭 카드로 표시되며, 최근 12주 고정 데이터(주간/월간 실제 기록 탐색과 무관)를 사용한다.

### 18.7 업무시간 기록의 카테고리 (v9 신설)

- 업무시간 기록 한 건은 정확히 하나의 `categoryId`를 가진다 — 카테고리 선택은 저장 전 필수이며, 새 기록에 첫 번째 카테고리를 자동으로 대입하지 않는다(플레이스홀더 `카테고리 선택`이 선택 전 상태를 나타낸다).
- 이 카테고리는 **Work Log 전용 개념이 아니다.** Planning, Work Log 업무시간 기록, 향후 시간 캘린더, 향후 계획 대비 실적 분석이 공유하는 단일 사용자 소유 `ActivityCategory` 모델(`frontend/lib/api/types.ts`)이다. Work Log만의 별도 카테고리 타입이나 테이블은 두지 않는다.
- `항목`(자유 텍스트)과 카테고리는 계속 별개 필드다 — 카테고리가 항목을 대체하지 않는다.
- 루트·자식 카테고리 모두 선택 가능하다. 자식 카테고리는 `상위 > 하위` 형식으로 표시한다.
- 신규 선택 가능한 옵션은 **활성** 카테고리뿐이다. 다만 이미 저장된 기록이 비활성 카테고리를 참조하고 있으면, 그 기록에 한해 `카테고리명 (비활성)` 형태로 계속 표시한다 — 비활성 카테고리를 새로 선택할 수는 없지만, 이미 참조 중인 기록에서 조용히 사라지거나 다른 카테고리로 바뀌지 않는다.
- 카테고리 이름은 항상 현재 카테고리 목록에서 실시간으로 조회해 표시한다 — 이름·상위 이름·색상 등을 업무시간 기록에 스냅샷으로 저장하지 않는다. 카테고리 이름이 나중에 바뀌면 기존 기록의 표시도 그에 따라 갱신된다(적용 출근 기준 스냅샷과는 반대되는 정책이다).
- 현재는 Work Log가 아직 목데이터 기반이므로, 카테고리 목록도 최소 규모의 목 카탈로그(`frontend/app/worklog/activityCategory.ts`)로 제공된다. 이 목록의 카테고리명은 실제 운영 데이터가 아니다. 추후 백엔드가 연결되면 `GET /api/activity-categories` 응답으로 교체될 예정이며, 그 전까지 카테고리 생성·수정·삭제·비활성화 UI는 Work Log에 두지 않는다(카테고리 관리는 별도 화면의 몫이다).

### 18.8 유예됨 (구현 차단 아님)

- 정시 출근 처리를 대체할 공식 근태 예외/승인 요청 워크플로.
- `isOnTimeOverride`의 백엔드 영속화·API 계약.
- 미사용 `actualBlockMinutes` 필드/선택자 정리 (현재는 UI에서 안 보일 뿐 보존됨).
- `AppliedStartTime` 유니온의 `source: "custom"` 호환 분기 정리 (현재 UI/목데이터 어디서도 생성하지 않지만 타입은 보존됨).

## 19. `일` (daily) 뷰

### 19.1 모드 및 탐색

- 근무 기록 섹션의 기간 단위가 `일`/`주`/`월` 세 가지로 늘어났다 — `일`이 첫 번째 탭이다. 주간/월간 모드의 기존 동작(탐색 상태, 컬럼, 요약, 행 클릭 등)은 전혀 바뀌지 않는다.
- `일`을 처음 선택하면 오늘 날짜로 초기화된다. 이후 세션 동안 마지막으로 선택된 날짜를 기억하며, 주/월로 전환했다가 다시 돌아와도 유지된다.
- 툴바는 `이전 날` / 선택된 날짜(`2026.08.24 (월)` 형식) / `다음 날` / `오늘` / 기존 `출근 기준` 버튼으로 구성된다. 검색/필터/열 설정/페이지네이션은 없다.

### 19.2 목적과 구조

- `일` 뷰는 하루치 업무시간 기록을 연속적으로 입력하기 위한 화면이다 — 통합 레코드 수정 모달(§18.4)을 대체하지 않으며, 출결/출퇴근/점수 등 다른 필드는 다루지 않는다. 오직 `workTimeEntries`만 이 화면에서 변경된다.
- 테두리 있는 전체 폭 카드 하나로 구성: 헤더(제목 `업무시간 기록`, 날짜, 출결 상태색 텍스트, 저장되지 않은 변경사항 표시), 본문(공유 `WorkTimeEntryEditor`, 실근무 합계 포함), 푸터(`변경 취소`/`변경사항 저장`).
- `WorkTimeEntryEditor`는 통합 레코드 수정 모달과 `일` 뷰가 함께 재사용하는 유일한 구현체다 — 두 번째 구현은 만들지 않는다.

### 19.3 초안·저장·취소

- 선택한 날짜가 이미 페이지 레벨 상태(오늘/주간/월간/추이 4개 데이터셋 중 하나)에 존재하는 **추적된 레코드**일 때만 로컬 초안이 만들어진다 — 그 레코드의 `workTimeEntries`로 초기화한다. 타이핑 중에는 페이지 레벨 Work Log 상태를 건드리지 않으며, 저장된 값과 다를 때만 "저장되지 않은 변경사항"으로 표시된다.
- 추적되지 않은 날짜(위 4개 데이터셋 어디에도 없는 날짜)는 §19.5의 레코드 없음 상태로만 표시된다 — 이 경우를 위해 임시 레코드를 즉석에서 만들지 않는다. 그렇게 만든 임시 레코드는 페이지를 벗어났다가 돌아오면 다시 새로 생성되어 이전 입력을 조용히 잃어버리므로, "저장됨"처럼 보이지만 실제로는 세션 동안 유지되지 않는 거짓 상태가 되기 때문이다. 레코드 생성 자체는 향후 백엔드 WorkRecord API의 책임이다.
- `변경사항 저장`: 기존 업무시간 검증을 통과해야 하며, 통과하면 페이지 공용 업데이트 경로(`updateRecordForDate`)로 `workTimeEntries`만 반영한다 — 오늘 요약/주간 테이블/월간 테이블/통합 레코드 수정 모달/주간·월간 요약/근무 추이 차트 등 같은 날짜를 참조하는 모든 화면이 자동으로 갱신된다(별도 계산 로직 없이 기존 selector 재사용).
- `변경 취소`: 저장된 값으로 되돌리고 검증 오류를 지운다. 변경사항이 없으면 두 버튼 모두 비활성화된다.
- 자동 저장은 없고, 브라우저 저장소에도 남기지 않는다 — 새로고침하면 원본 목데이터로 돌아간다.

### 19.4 저장하지 않은 변경사항 가드

- 다음 시점에 초안이 dirty 상태면 이동 전에 확인 모달을 띄운다: 이전/다음 날 이동, 오늘 이동(날짜가 바뀌는 경우), `일→주`/`일→월` 전환, 오늘 요약에서 다른 날짜의 dirty 초안이 남아있는 채로 `일` 뷰를 여는 경우.
- 확인 모달은 제목 `저장하지 않은 변경사항을 버릴까요?`, 버튼 `계속 편집`(기본 포커스)/`변경사항 버리기`(destructive) 뿐이며 본문 설명 텍스트는 없다. `계속 편집`은 날짜와 초안을 그대로 두고 포커스를 되돌리며, `변경사항 버리기`는 초안을 버리고 원래 요청했던 이동을 완료한다.

### 19.5 비근무일 처리

- `근무`/`조퇴`만 편집 가능하다. `휴일`/`연차`/`병가`는 읽기 전용 안내(`근무 또는 조퇴 기록에서만 업무시간을 입력할 수 있습니다.`)만 보여주고 입력을 막는다 — 이미 남아있는 업무시간 기록이 있다면 삭제하지 않고 읽기 전용 목록으로 함께 보여준다.
- 선택한 날짜가 추적된 4개 데이터셋 어디에도 없으면 `선택한 날짜의 근무 기록이 없습니다.`만 표시한다 — 편집기, `변경 취소`/`변경사항 저장` 모두 렌더링하지 않는다. 새 레코드를 만들거나, 다른 데이터셋을 조용히 변경하거나, 임시 레코드를 저장 가능한 것처럼 보여주지 않는다. 날짜 선택 자체와 이전 날/다음 날 이동은 이 상태에서도 그대로 동작한다.

### 19.6 오늘 요약 연동 및 독립 모달 제거

- 오늘 요약의 `업무시간 기록` 버튼은 더 이상 독립 모달을 열지 않는다 — 기간 단위를 `일`로 전환하고, 오늘 날짜를 선택하고, `일` 카드로 스크롤한 뒤 카드 제목으로 포커스를 옮긴다. 라우팅 변경도 새로고침도 없다. 이동 전에는 §19.4의 dirty 가드를 그대로 거친다.
- 과거 존재했던 독립 `WorkTimeEntryModal`(업무시간 기록 보기 전용 모달)은 완전히 제거되었다 — 호출부가 하나도 남지 않아 컴포넌트 파일 자체를 삭제했다. 통합 레코드 수정 모달에 임베드된 `WorkTimeEntryEditor`(§18.4)는 그대로 유지된다.
