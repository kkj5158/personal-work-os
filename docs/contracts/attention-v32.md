# WORK QUEUE V3.2 connection contract

New producer issuance and S256 device exchange persist an owner-scoped, SHA-256 hashed, 256-bit random bearer grant with `expires_at NULL`. Explicit revocation is irreversible and checked on every authentication. Tokens retain the aqp_/aqd_ formats and the exact existing AttentionSecurity scope/rate limits. There is no refresh token or native/client deployment in this release. Long-lived bearer theft remains a risk: keep secrets in existing private/OS-protected client storage; rotate manually by issuing/pairing a new key, configuring the client, then revoking the old key.

The installed Windows client requires `expiresAt` to be an RFC3339 string and rejects expired stored credentials locally. Issuance/exchange therefore return `expiresAt:"9999-12-31T23:59:59Z", persistent:true` as a legacy wire compatibility sentinel, while database authorization has no time limit. One-use authorization codes keep the 120-second expiry, S256, state, installation and loopback constraints. Existing expired Windows credentials require fresh pairing from that installation; a new pairing revokes only its previous device credentials. No Windows/Chrome collector or updater is changed.

GET /api/workflow/attention/devices remains owner-authenticated and exposes no secret. Additive fields: `persistent:boolean`, `lastUsedAt: RFC3339|null`. Legacy expiration values remain unchanged. Persistent listings also use the same compatibility sentinel with `persistent:true`, avoiding invalid dates in the old Web UI during the API-before-Web deployment interval. The new Web tolerates nullable expiry payloads too. Last-used records a successful credential authentication attempt (including an attempt whose route is subsequently refused), with at most one row write per five minutes; it does not prove online presence.

POST /api/workflow/attention/devices/{id}/restore requires the normal POS owner session. It returns 204, 404 for another owner's/missing ID, and 409 for revoked or DEVICE records. For a non-revoked PRODUCER, explicit owner confirmation removes the expiry (also allows deliberate conversion of a still-active legacy producer), preserving the hash/identity/namespace/creation time. Repeated restore is a no-op; a RESTORE audit event is stored only for an actual conversion. Row locking and a revoked_at predicate prevent resurrection after revocation. DELETE /devices/{id} is owner-scoped and idempotently preserves the first revocation timestamp. Attention bearer credentials cannot administer connections.

V115 only relaxes credential expiry nullability and adds nullable activity/audit storage with RLS. It does not update existing grants, queue items, lanes, ownership, history, ordering or existing migrations. Existing expired keys stay expired; revoked keys stay revoked. No bulk PROD restore is performed.

The modal native dialog drawer uses the browser top layer for inert background/focus containment, Esc, explicit close, focus restoration and mobile full width. Keys exist only in React memory and clear on closure, tab backgrounding, section/type change, owner change or unmount. Existing hidden-item history/reopen behavior remains reachable inside settings. The board/group/stack behavior is retained.

Rollback: preserve V115 and user data. Older API code cannot map NULL expiry and must not be redeployed after a persistent key is issued. Use a compatible forward fix; do not down-migrate, bulk re-expire or revive grants. Recheck actual release SHA and newer migrations under the common release lock before any recovery.
