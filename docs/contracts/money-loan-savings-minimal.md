# Minimal Loan and Savings — 2026-10-28

This current task supersedes schedule-oriented historical Loan proposals. One canonical transaction remains authoritative.

* Savings display semantics are additive response/query values: display_type=SAVINGS (저축), SAVINGS_WITHDRAWAL (저축 회수), or TRANSFER (이체). Database type remains TRANSFER. The unified ledger derives the value from both owned accounts' fund groups as of the outgoing transaction time; incomplete or unknown-history transfers cannot claim savings. SQL filtering uses the same expression before counts, pagination, search and period filters.
* The financial popover retains PR #3/#4 behavior. Savings choices guide actual counterpart selection with occurrence-time compatible candidates and send the existing versioned LINK_TRANSFER command. UI intentions never enter the canonical type enum or command payload. Linked transfers expose their derived label without requiring unlinking.
* Monthly Savings and Overview use confirmed active facts only, occurrence-time groups and account statistics inclusion. Unknown group history suppresses an authoritative savings total; no positive or negative contribution is guessed. Existing currency guards remain.
* All outstanding confirmed loan principal includes ACTIVE, PAUSED, INACTIVE and COMPLETED nondeleted profiles. Lifecycle status does not erase debt. Web Overview, current stock and Mobile fund totals share that scope. Legacy Mobile schedule fields stay present and retain ACTIVE-only schedule scope.
* Loan responses add linkedFactCount (including cancelled source facts) and unresolvedAllocationCount (active unresolved repayments). Existing Android ignores unknown JSON keys. Once any loan fact exists, opening principal cannot be overwritten; correction uses the same canonical payment. Registration creates no receipt fact.
* Web Loan lists/details prioritize remaining principal, status, unresolved allocations and same-transaction history. No future schedule controls or unreliable historical progress estimate. Existing optional schedule/date data stays persisted and round-trips unchanged in edits.
* Only a complete confirmed split reduces principal and adds interest/fees to consumption. Unresolved splits change cash once, without inferred principal/cost. On the repayment allocation path, attached bank evidence locks the original account, total withdrawal and occurrence time. Manual backdated corrections remain versioned. Loan relinking restrictions remain; inactive/completed debt requires a deliberate lifecycle reopening before incompatible correction.
* Savings management reuses Accounts, reconciliation provenance, monthly contribution detail and unified transfer filters. No goal/schedule/forecast engine, new menu, new ledger, or MONEY schema migration.

Validation and actual release state are recorded in the dated release report. Runtime tests use only run-owned synthetic loopback databases. Production financial mutation tests are prohibited.
