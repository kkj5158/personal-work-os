## 기존 원장의 확장

- V100은 `money_transactions.meaning_state`를 추가한다. 기존 행은 모두
  `CONFIRMED`이며 과거 유형을 자동 변경하지 않는다.
- 검증된 한쪽 현금 이동은 `UNRESOLVED`로 등록할 수 있다. 이때 기존
  INCOME/EXPENSE 값은 입출금 방향을 보관하는 호환 필드다. 의미 확정은
  `meaningState`/`meaning_state`로 구별한다. 소비·수입 통계는 확정 행만 읽는다.
- 잔액 계산에는 실제 방향·금액을 한 번 반영한다. 유형 확정·대출 배분은
  같은 거래 ID를 수정하며 추가 출금·입금을 생성하지 않는다.
- 한쪽만 확인된 TRANSFER는 다른 계좌를 null로 보관한다. 순저축은 실제 양쪽
  소유 계좌와 거래 당시 자금 그룹이 확인된 기존 투영만 계산한다.
- 원거래 미연결 REFUND는 현금 입금만 반영한다. 소비 차감은 원거래 연결 후
  환불 발생 월에 귀속하며 원거래의 가계부 분류를 상속한다. 환불의 직접
  override는 상속보다 우선한다. 초과 환불 연결은 거절하고 현금은 보존한다.

## 명령·복구

`/api/money/bookkeeping/unified`는 기존 원장 조회와 TYPE/CORRECT/
LINK_TRANSFER/UNLINK_TRANSFER/UNDO_UNLINK/ATTACH_SOURCE 명령을 제공한다.
모든 쓰기는 기존 owner advisory lock과 `MoneyCommandService`를 사용한다.
요청 ID는 본문에 결합되며 APPLIED/NOT_APPLIED/UNKNOWN 결과를 조회한다.
동일 ID를 다른 본문에 재사용할 수 없다. 결과 미확인은 같은 요청으로만
재확인하며, 버전 충돌 뒤 새 명령은 최신 값과 제안을 명시적으로 비교한다.

일괄 유형 확정은 항목별 요청 ID·버전을 가진다. 미리보기는 적격·제외 사유를
제공하고 각 항목은 독립적으로 커밋한다. 성공 재생은 추가 반영하지 않는다.
실패 항목만 최신 상태로 다시 미리보기 할 수 있다.

이체 해제는 이미 존재하던 양쪽 현금 효과를 독립 미확정 행으로 보존한다.
Undo는 양쪽 버전과 새로운 환불 종속 관계를 확인한다. 은행 원문과 관측 잔액은
수정하지 않는다. 은행 출처가 있는 계좌 정정은 원본의 소유 계좌 근거가 새
계좌를 지지할 때만 허용한다. 단순 사유 입력은 은행 근거를 대체하지 않는다.

## UI 및 범위

기존 가계부의 KPI 4개, 도넛 3개, 추천/직접 분류 선택기, 월간 필터,
그룹 계좌 선택, 제목·메모 저장과 하단 요약을 재사용한다. 전체 거래는 같은
페이지의 추가 탭이다. `/money/transactions`는 같은 통합 가계부를 연다.
잔액 점검의 상세 워크스페이스와 계좌·대출 전면 개편은 후속 범위다.

원본 은행 알림이 제공하지 않는 대출 식별자·원구매 식별자를 금액/이름만으로
추정하지 않는다. 현재 파서가 제공하지 않는 강한 연결 근거의 자동화,
Android의 미확정 표시·충돌 비교 UI 및 실제 hosted DEV 인증 검증 여부는
정책별 구현 매트릭스에서 별도로 판정한다. 로컬 테스트 PASS를 그 항목의
DEV 종단 검증 PASS로 확대하지 않는다.

## 마이그레이션 및 복구

V100은 추가 컬럼·인덱스와 한쪽 이체를 허용하는 확장 제약만 적용한다.
기존 거래 ID·금액·버전·원문·체크포인트는 변경하지 않는다. 적용 전 Flyway
현재 버전/충돌을 확인하고 적용 후 validate 및 부팅 로그를 확인한다.
새 미확정/한쪽 이체가 없을 때만 이전 서버로 되돌릴 수 있다. 새 의미 상태가
사용된 뒤에는 이를 무시하는 이전 서버로 롤백하지 않고 수정 버전으로
전진 복구한다. 과거 행을 임의 소비로 일괄 확정하는 복구는 금지한다.

## 2026-10-27 누적 수정 01–03

- 일반·전체·저축 거래 표는 `일시`와 `금융 유형`을 분리한다. 금융 유형은 기존
  `카테고리` 바로 왼쪽이며, 분류 선택기와 인라인 저장은 기존 컴포넌트를 사용한다.
- 가계부 표의 행·건수·선택은 canonical 거래 조회만 사용한다. `/processing` 원시
  알림은 표에 합성하지 않는다. 원문과 검토 큐는 보존하며, 등록된 거래는 원본에
  검토 경고가 있어도 제외하지 않는다. processing polling은 새 등록의 갱신에 유지한다.
- Bookkeeping 응답의 추가 `financialType`은 canonical 유형이다. 기존 `type`은
  분류/통계 호환용으로 대출 이자·수수료를 EXPENSE로 계속 투영한다.
- 대출 배분 정정은 입력하지 않은 항목의 기존 값을 포함한 전체 분할을 보낸다.
  명시 null은 배분 미확정 또는 환불 연결 해제 의도로 보존한다. 수입 의미 확정도
  현재 유효 규칙을 재평가하고 직접 override를 보호한다. 일괄 replay 역시 원래
  requestId와 명령 본문의 결합을 검증한다. 마이그레이션과 과거 일괄 변경은 없다.
