# POS shell preferences

Top-level system order is a user-global preference independent of workspace, current route, system identity and Global Tab order. The switcher opens `시스템 순서 설정`; only this modal exposes drag handles, including keyboard sorting. Changes autosave immediately through a serialized writer. Failed saves retain the requested order and offer retry. Reset stores an empty custom order. Known systems absent from the saved order append in default order; retired IDs are ignored.

`GET /api/pos/preferences/system-order` and `PUT /api/pos/preferences/system-order` return `{ "systemIds": ["work", "notes", "diet", "life", "calendar", "workflow", "authoring"] }`. The PUT body has the same shape; an empty list resets to defaults. IDs are stable lowercase identifiers. Each request resolves its owner from CurrentUserProvider, never from client input. V47 adds `pos_system_order(owner_id, system_ids, updated_at)`; the row stores the custom list, not route or editor content.

The root shell persists during client navigation. Route modules unmount normally. A bounded shell-lifetime memory cache retains opted-in view state (Worklog date/period) and main scroll positions; login clears it. Existing domain save/discard guards remain authoritative, and failed leave saves keep the page mounted with a retry action. Worklog also guards cross-system navigation and browser unload for daily rows, Today memo/score and record-editor drafts. Conflict responses retain the editor until an explicit discard/reload succeeds; failed reloads preserve the draft. Route render errors offer reset at the current URL. Real authentication expiry still returns to login with the requested URL; transient authentication service failures and unavailable auth configuration fail closed with 503 at the requested URL.
