# Bank-native reconciliation command contract

The canonical MONEY reconciliation pipeline supports bounded owner-scoped repair. Import is encrypted staging; it never posts money. The normalized BANK_NATIVE_REPLAY_V1 transport preserves original file SHA-256, authoritative row hashes, native sheet/row coordinates, signed KRW movements, balance chain and SECOND/DAY precision. It does not authenticate the original bank file: verification remains OWNER_ATTESTATION_REQUIRED until the owner approves that exact source hash and frozen financial preview. Do not upload bank passwords or original files to reports.

Use money_recon_intake_start/chunk/import_statement_preview, money_recon_analyze and money_recon_list_rows. Preview up to 50 unique rows across at most five exact statement IDs with money_recon_batch_preview. Include current transaction/account/raw/loan versions and attestNativeSource only when presenting that source attestation to the owner. Preview returns account impacts, source-cutoff balances before/after, statistics, immutable target set, previewId, fingerprint and ten-minute expiry. No financial posting occurs during preview.

Supported actions include bank-side unresolved cash admission; notification-paired canonical transfer admission; source-only linking; explicit held-review completion; bounded old-parser repair; paired-source transfer endpoint correction; bank-timeline checkpoint correction; constrained opening-window anchor correction; separate overdraft facility mapping; bank interest allocation with principal zero; and account-specific bank clock alignment. Existing raw notifications and parse attempts are retained. The bank time belongs to the proved account side; the ledger timestamp and other account side remain independent. Unknown merchant/category/counterpart stays unresolved.

For an already booked Kakao Gateway movement, the bank reconciliation API can preview COMPLETE_BOOKED_TRANSFER. The existing immutable checking cash claim, original linked parse, exact bank amount and after-balance, and both registered owned endpoints must agree. The missing endpoint must be a purpose savings account linked to that Gateway. The command completes the existing transaction and preserves its cash amount, time and source links. Its versioned receipt supports UNDO_CHANGE.

Execute money_recon_batch_execute only after fresh approval of the exact preview and source hashes. Send the original requestId, previewId, fingerprint and confirmed=true. Global owner ledger/source/account/loan/checkpoint snapshots are rechecked under the canonical owner lock; expiry, changed data, versions, source ambiguity and cross-tenant IDs fail closed. A timeout requires money_get_operation_outcome using the ORIGINAL request ID. Do not repeat with a new ID before recovering the outcome. money_recon_list_history returns durable receipts and per-item change IDs.

For supported compensations, preview UNDO_CHANGE with the original rowId and changeId in transactionId, current subject/account version, current loanVersion when relevant and an explicit reason. The original command receipt and subsequent version guards must still match. Cash compensation invokes canonical registration cancellation; it never deletes the original fact or source. Checkpoints restore prior business values; endpoint correction restores original endpoints/type; facility undo deactivates the mapping; bank clock undo appends a compensating clock audit. Reparse history remains immutable. Source links remain as historical evidence; use a fresh reconciliation to determine current active economic coverage after cancellation. Source repairs and unsupported semantic edits require their canonical correction workflow or a carefully scoped recovery from the independently tested owner-only encrypted backup. Never restore an old full snapshot over newer owner activity.

Overdraft facilityLimit, registered historical principal and usedPrincipal are separate. Current utilization is max(0, -canonical bank-account balance) with a stated as-of basis; missing basis is unknown. Net worth removes that negative account from asset double counting and replaces the registered facility principal in debt with utilization. Interest remains consumption; facility principal movements are transfers, not spending. money_get_overdraft_facilities exposes this basis. Seven accounts outside supplied statements remain independently SOURCE_MISSING.

Validation uses synthetic PostgreSQL fixtures, an isolated restored owner-copy rehearsal, MCP schema tests, frontend build and disposable DEV hosted OAuth/MCP verification. Owner financial execution is separate from disposable-fixture execution. A hosted SDK call is not evidence of a fresh in-chat connector call; report that boundary explicitly.
