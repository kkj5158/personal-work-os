## Gate B: 안전한 구현 순서

1. 원래 UI·Review·대출·저축·환불 계약을 보존하고 baseline을 위와 같이 기록한다.
2. 일반/전체/저축 표의 금융 유형 열을 분리한다. W에 financialType을 추가하되 분류용 type=EXPENSE 호환을 유지한다.
3. 가계부의 원시 processing row 합성을 제거한다. 기존 canonical 조회·페이지 수·선택을 그대로 사용한다. Review 기능은 수정하지 않는다.
4. 대출 분할 draft의 기존 값/명시 null/부분 수정 payload, 환불 연결 해제 null 처리, 수입 확정 규칙 재평가, bulk replay 본문 검증을 고친다. 각각 재현 테스트 후 회귀한다.
5. 격리 합성 DB에서 금융 회귀 및 실제 API 검증, frontend typecheck/lint/build, TEAM KAFKA의 같은 화면에서 전후·분류 저장·대출 분할을 검증한다. 공유 DEV/PROD 금융 데이터는 fixture로 사용하지 않는다.

새 enum·마이그레이션·기존 금융 데이터 backfill은 현재 발견된 문제 해결에 필요하지 않다. 자동 대출/환불/지연 콜백 식별은 승인된 강한 식별 근거가 없으므로 해당 자동화만 보류한다. 계좌 상세·대출 관리·잔액 점검 전면 UX 및 Android 신규 화면은 이번 수정 범위 밖이며 서버 호환·무결성은 회귀 대상이다. DEV 배포는 현재 저장소 정책의 exact-SHA 검증과 정상 승인 범위 안에서만 진행한다. PROD 변경은 금지한다.
