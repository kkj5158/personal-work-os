## 구현 결과

기존 캘린더 안에 날짜 없는 월~일 시간표 탭을 추가했다. 시간표 생성·정보 수정·정렬·전체 복제·보관·복원,
설명/목표/메모가 여러 줄로 표시되는 상세 카드, 독립적인 좌우 패널 접기와 기본 배치 복원을 제공한다.
카드와 보조 정보는 같은 초안을 사용한다. checklist 항목 수정·순서·체크 상태도 저장한다.

블록은 클릭·드래그 생성, 다중 요일 생성, 요일 이동·리사이즈, 상세 폼, 복제·삭제·실행 취소를 지원한다.
15분 스냅과 1분 직접 입력, 겹침 레인, 월→화/일→월 자정 연결, 명시적 다음 날 종료와 24시간 길이를 처리한다.
저장 실패는 이전 배치로 복구하고 버전 충돌은 초안을 보존한다. 기존 날짜별 일정·Actual·통계는 변경하지 않는다.

오른쪽 운영 철학은 기존 `frontend/app/notes/editor/NoteEditor.tsx`와 `NoteEditorSource`를 재사용한다.
정규 Markdown, 제목·강조·기울임·인용·목록·체크·링크·코드, 텍스트/HTML 붙여넣기, 키보드 Undo/Redo와 검색을 유지한다.
기존 Autosave의 IME 보류·직렬 저장·실패 재시도·초안 복구·명시적 충돌 해결을 그대로 사용한다.
시간표 ID별 editor/저장 큐를 유지하며 확대와 패널 접기에도 같은 문서를 편집한다. NOTE 문서는 자동 생성하지 않는다.
Workspace 전용 이미지 업로드·태그·위키 대상 탐색·노트 pin/trash는 기존 source 어댑터 경계에 따라 제공하지 않는다.

색상은 `frontend/app/calendar/CategoryColorPicker.tsx`와 `appearance.ts`의 12색·최근 8색·직접 지정·기본 복원을 재사용했다.
명시 블록색 > 시간표 기본색 > 공통 fallback 순서이며, 글자 대비와 폼 취소를 처리한다.
picker의 native dialog portal 및 scroll/resize 위치 갱신을 보완했다. 기존 카테고리 저장/상속은 유지한다.

## 제한과 실패를 구분한 기록

- 변경하지 않은 기존 `calendarContext.test.tsx`의 shell 메뉴명 assertion 1개는 `LIFE CODE` 기대값과 현재 `LIFE OS` 표시 차이로 실패했다.
  관련 원본 파일은 이번 변경과 동일하다. 이를 신규 기능 PASS에 합산하지 않았다.
- 최초 tsc의 LayoutProps 미생성 오류는 `next typegen`/실제 build 후 해소됐다. 신규 security 테스트가 발견한 누락 header 500은 controller 400 처리로 수정했고 최종 4/4 통과했다.
- 마지막 owned runtime은 31개 백엔드 테스트와 migration을 통과했으나 의존성 재설치와 Web 기동이 겹쳐 전체 runner는 환경 실패로 종료했다.
  전체 runner PASS로 보고하지 않는다. 이후 별도 PROD 후보 build와 실제 hosted DEV/PROD 확인은 통과했다.
- hosted 브라우저가 background/hidden 상태라 일부 정상 click/check가 actionability timeout을 냈다. 해당 조작은 지원되는 DOM UI activation과 실제 인증 API 응답으로 검증했다.
  로컬의 실제 포인터/키보드 검증과 구분한다. hosted screenshot도 timeout이어서 PASS로 기록하지 않았다. 제공 이미지 7개는 합성 데이터의 로컬 DEV 시각 증거다.
- 처음 hosted 철학 확인은 UI 저장 상태만 기다려 DOM observer와 경합했다. 보강 검증은 실제 PUT 200 응답을 기다리고 정확한 저장 본문을 reload로 확인했다.
- 기존 PROD PITR는 비활성 상태다. 설정/유료 플랜/DB 이미지를 변경하지 않았다. 이번 migration은 새 테이블 생성만 하며 기존 데이터 변환이 없다.
