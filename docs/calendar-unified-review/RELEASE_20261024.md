## 마이그레이션

DEV는 기존 v96에서 V97 한 개를 적용했다. 운영은 기존 v94에서 V96, V97 두 개를 적용하여 v97로 기동했다.
Railway 실제 기동 로그에서 validate 성공, 적용 version/file, 적용 개수와 prod/PROD 기동을 확인했다.
운영 DB에 직접 SQL을 실행하거나 Flyway history를 수동 수정하지 않았다.

- V96: 기존 reflection_entries에 nullable 일일 annotation 컬럼과 범위 제약 추가.
- V97: owner + Monday unique 및 version/CAS를 갖는 calendar_weekly_reviews 테이블 생성.
- 격리 PostgreSQL의 checksum: V91 `1621045375`, V94 `294450930`, V96 `787826698`, V97 `1589858103`, 모두 success=true.
- 위 checksum 숫자는 격리 DB readback이다. hosted PROD에서 직접 checksum SQL을 조회한 것으로 표현하지 않는다.
- 운영에 없는 V90/V95를 이번 release가 적용하지 않는다. 향후 해당 기능 승격 시 낮은 migration version과 out-of-order 정책을 다시 검토한다.
