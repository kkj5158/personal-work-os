# Sleep Web V2 수면 캘린더 / LIFE OS 통합 캘린더 — 검토용 경계

## 1. 이번 목업에서 확정 요청하는 화면 역할

- **수면 전용 캘린더:** Sleep Web의 기본 작업 화면. 야간 수면과 낮잠의 시간대 분포를 주간 시간축에서 정확히 보여주고, 세부 시각 확인과 수정에 집중합니다. 일별 / 주간(기본) / 월간 전환을 유지합니다.
- **LIFE OS 통합 캘린더:** 추후 별도의 LIFE OS 화면. 운동·수면·낮잠 등 각 도메인 원본 데이터를 하나의 시간축에 합성해서 표시합니다. 이번 HTML에서 통합 캘린더 기능이나 운동 데이터 API를 새로 구현하지 않습니다.
- **디자인 참고:** 사용자가 제공한 `LIFE_OS_EXERCISE_CALENDAR_FINAL_20261013.html`의 PC 정보 밀도, 흰색 패널, 24시간 축, 종류별 색상, 블록 상세 편집, 월간 일자 셀을 참고하되, Sleep 전용 화면의 책임을 유지합니다.

## 2. 표시 정책

- 주간 기본 보기: 전날 18:00부터 해당 수면일 18:00까지, 최근 7일. 이는 수면 전용 화면의 편의상 표현이며 통합 캘린더의 00:00~24:00 일자 축과 구분합니다.
- 주간 블록에는 야간 수면·낮잠의 **실제 시작/종료 시각과 길이**를 표시하고, 선택 시 상세 입력에서 양끝 날짜를 확인합니다. 색상은 야간 수면 보라, 낮잠 녹색을 사용합니다.
- 월간 셀의 `야간`, `낮잠` 숫자는 기존 Sleep 원본의 귀속일 기준이며, 셀 하단의 색상 띠는 **해당 달력 날짜 00:00~24:00에 실제로 걸쳐 있는 시간**만 표시합니다. 두 값의 날짜 의미는 명확히 구분합니다.
- 최근 평균 정책 유지: 야간 수면은 유효한 완료 기록 기준 평균, 낮잠은 1회당 평균. 미기록은 0시간으로 계산하지 않습니다.

## 3. 원본 소유·조회·수정 경계 (향후 통합 캘린더를 위한 구현 주의)

- 야간 수면·낮잠 원본은 Sleep 도메인이 소유합니다. 별도의 통합 캘린더용 수면 사본을 생성하거나 수면 수정 전용 새 복제 API를 만들지 않습니다.
- 통합 조회 데이터의 필수 개념: `sourceType`, `sourceId`, 정확한 시작·종료 timestamp, Sleep 원본 귀속일, 수정 가능 여부, 원본 revision/동시 수정 판단 정보. 필드명·API는 기존 구현 실사를 통해 결정합니다.
- 범위 조회는 **귀속일과 무관하게 실제 시간 구간이 범위와 교차하는 레코드**를 돌려주도록 검증합니다. 주간 수면 전용 보기와 00:00~24:00 통합 보기는 같은 원본 ID를 가리킵니다.
- 10월 12일 23:15 ~ 10월 13일 07:30 수면은 **한 건**입니다. 화면에서는 경계 양쪽에 걸쳐 표시될 수 있어도 저장·수정·동기화할 때 분할하지 않습니다.
- 드래그 이동은 구간 길이를 유지하며 두 끝을 옮깁니다. 위·아래 핸들은 해당 끝점만 수정합니다. 두 방식 모두 기존 Sleep의 명시 저장·revision·충돌 처리·오프라인 복구 경로를 거칩니다.
- 저장 실패/중복 응답/다른 클라이언트 동시 편집은 기존 Sleep 정책에 따라 사용자 수정안을 보존하고 자동 덮어쓰지 않습니다. 성공 후 관련 데이터 조회·통계가 갱신되어야 합니다.
- 화면 시간대는 기본 `Asia/Seoul` 표시, 저장·교환은 기존 timestamp/timezone 계약을 유지합니다.

## 4. 아직 결정하지 않은 항목

- 통합 캘린더의 주간 기본 보기 및 시간 눈금.
- Sleep / 운동 사이의 시간 충돌 차단 여부.
- 통합 캘린더의 Undo 및 일정 삭제 정책.
- 기존 범위 조회 API와 실제 수정 충돌 계약의 구현 간극.

본 HTML은 **로컬 샘플 데이터로 실행되는 UI 검토 목업**입니다. 실제 서버, Android 동기화, 운동 원본을 연결하지 않았습니다. Sleep Web 배포는 변경하지 않았으며, 사용자 승인 전에는 구현 명세의 최종 정본으로 간주하지 않습니다.
