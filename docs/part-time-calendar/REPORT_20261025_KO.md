## 데이터 보존과 마이그레이션

`V99__money_workplaces_multi_shift.sql`은 `money_workplaces`와 기존 template/work/earnings-week의 `workplace_id`를 추가한다. 기본 쿠팡 ID는 owner별 `md5('money-workplace:coupang:' || user_id)::uuid`이며 재실행 시 중복을 만들지 않는다.

기존 template·work·weekly JSON, version, last_request, updated_at, payment 행은 migration이 변경하지 않는다. FK/index만 확장하며 work 날짜 unique와 earnings-week owner/week unique를 각각 다중 근무·근무지별 주간 제약으로 대체한다. 참조가 없는 과거 근무도 기본 근무지로 연결한다.

기존 중첩 preset ID/정의를 공유 catalog에 보존한다. 같은 owner에서 같은 ID에 상충 정의가 있으면 자동 수정하지 않고 migration이 중단된다. 실제 공유 데이터에 충돌이 있는지는 미확인이다. 구 binary rolling INSERT의 기본 근무지와 template-local preset UPDATE는 trigger로 호환 연결한다. 신규 API는 근무지 preset을 template DTO에 projection하고 버전 충돌을 검증한다.

격리 PostgreSQL에서 legacy fixture 생성 → migration 두 번 실행 → ID·JSON·version·last_request·updated_at 및 payment의 ctid/JSON 비교를 통과했다. 확정 일급·포함 인센·입금 확인이 catalog 변경/보관/복원에 영향받지 않는 것도 검증했다. **이는 실제 DEV/PROD 금융 데이터 전체 보존을 검증한 결과가 아니다.**
